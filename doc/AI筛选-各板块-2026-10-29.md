# AI 价值筛选(各板块推送前过滤)—— 2026-10-29

> 用户口径:「你群信息有点杂乱啊,需要自己筛选,能不能让 AI 筛选出有价值的热点出来,
> **每个板块都加上 AI 筛选**」。

## 一、它做什么(只做一件事)

推送前给每条内容打 **0~10 分**:「这条能不能变成一份让人愿意**转存**的网盘资源」。
低于分数线(`AI_FILTER_MIN_SCORE`,默认 6)的不推;留下的按分数从高到低排。
卡片头上会写 **`AI筛8/20`**,让人知道筛过、筛掉多少。

判据(写在提示词里,不是词表):
- 有具体文件/资源(资料、软件、游戏、课程、模板、安装包…)→ 高分;
- 纯广告、没有具体资源、纯情绪八卦、几个月前的旧帖 → 低分。

为什么不用规则词表:`niche_fit` 与 `gossip_topics` 都验证过 —— 关键词分不清
「公众人物」与「普通人」、「资源」与「资源型广告」,模型分得清。

## 二、三条纪律(每条都对着本仓的坑)

1. **失败一律放行**。模型超时 / 没配 key / 返回垃圾 ⇒ 原样全推,`source="fallback"`,
   卡片上**不写** `AI筛x/y`。宁可吵,不可「看起来筛过了其实全丢了」。
2. **按标题做进程内缓存**。热榜类 20 分钟一轮、同一标题反复出现;
   不缓存同一句话一天要付几十次钱。
3. **只判前 N 条**(`AI_FILTER_MAX_ITEMS=40`),其余**原样放行**,并写日志。

## 三、已接入的板块(2026-10-29)

| 板块(section) | 推送点 |
|---|---|
| `douyin_peer` / `douhot`(抖音线索) | `douyin_leads.push_leads` |
| `douyin_peer`(抖音对标号) | `douyin_peer_scan.push_works` |
| `weibo/weibo_peer/xiaohongshu/kuaishou/tieba/bilibili/zhihu`(跨平台资源热度) | `resource_presence._push_group`(按平台分别判) |
| `zhihu`(公开平台新发现资源) | `pan_discovery.push_items` |
| `douhot`(抖音关键词趋势) | `douhot_window.run_feishu` |

**尚未接入**:公众号监听、闲鱼、迅雷群转存、多平台共振榜。
⚠️ 它们不是"忘了",而是**不能只加一行**:这些链的 `pushed_at` 同时承担"补推"语义
(没过 `pushed_at` 的下一轮会重推)。若 AI 挡掉却不打戳,被挡的条目会**每轮重判、永远补推**;
要接它们得先加一个"AI 挡掉 = 已处理"的状态位,那是下一步。

## 四、配置

```ini
AI_FILTER_ENABLED=true          # 总开关
AI_FILTER_SECTIONS=             # 留空=所有已接入板块;可写 douyin_peer,weibo
AI_FILTER_MIN_SCORE=6           # 分数线 0~10
AI_FILTER_MIN_KEEP=1            # 至少留几条(全被挡光时按分数补,不发空卡)
AI_FILTER_MAX_ITEMS=40          # 一次最多判多少条
AI_FILTER_TIMEOUT=45
DEEPSEEK_API_KEY=...            # 没配 ⇒ 整个筛选自动关闭(不报错)
```

## 五、成本与观测

- 每批(≤40 条)约 1~2K tokens;按标题缓存后,只有**新标题**才计费。
- `llm_client.llm_usage_snapshot()` 已统计 calls/failures/tokens(与叙事层共用计数器)。
- 失败会以 WARNING 落日志:`AI筛选[板块]失败 ⇒ 本轮不筛,N 条全部照推`。
