# 热点规律与监控(2026-11-08 起,2026-11-09 订正)

> 用户口径:「**每次都会有新的热点出来你需要总结这些规律来完成监控和预测**」
>
> 用户纠正:「**热点事件名称是没有关联性的,每一个都是独立的事件**」

本文回答三件事:**热点从哪来**、**能活多久**、**值不值得跟**。每一条都标了实测出处;
测不出来的也**如实写在最后一节**,不许当成"已做到"。

---

## 〇、那条纠正推翻了什么

上一版的设计是「**按种子族扩展**」:拿已知大瓜名当 keyword 定向查热点宝,靠
`_belongs()`(最长公共子串)判断是不是同一族。用户那句「每一个都是独立的事件」
直接否掉了这个前提 —— 用已知名字扩展,**只能找到已知事件的新说法**,
**永远发现不了全新事件**。

实证(`墨尔本七个小矮人` 定向查回的 50 个词,18 个是最近 2 天首现的):

```
墨尔本华人外卖员遇刺身亡      3286 万   ┐
墨尔本遇害中国骑手妻子发声    2502 万   │ 全是同一个事件的
熊猫外卖骑手于墨尔本遇害       603 万   │ 不同说法(13 种)
中国骑手墨尔本遇害             570 万   ┘
接亲七个枣核含义               379 万   ← 路人,只共用「七」这个字
```

⇒ 种子扩展**既发现不了新事件,又会带进路人**。要发现新事件**只能看全榜**。

## 一、热点从哪来:两条**不带种子**的通路(2026-11-09 实测)

| 通路 | 请求 | 条数 | 新鲜度 | 用途 |
|---|---|---|---|---|
| **小时搜索榜** | `hot_search(limit=50, date_window=1, sub_type=3001/3002)` | 50 + 50 | **小时级**,新事件日点 1~5 | ✅ **主通路** |
| 内容词榜 | `hot_words(limit=200, date_window=168)` | 200 | **日级且滞后**(11-09 测得末点仍是 11-07);`dw=72` 回 **0 条** | ⚠️ 只作热度参考 |

### 1.1 判「当天新起」的信号是**序列点数**,不是量

小时榜实测(`2026-11-09`):

| 词 | 末值 | 点数 |
|---|---|---|
| `黄仁勋发声明承认出轨` | 4693 万 | **2** |
| `现场观战BLG vs T1` | 398 万 | **1** |
| `blg对决t1比分` | 73 万 | **3** |
| `22年小孩游泳馆溺水后续` | 23 万 | **2** |
| `kpl` | 1463 万 | 24(满) |
| `仙逆` | 2189 万 | 24(满) |

⇒ **点数少 = 刚上榜**;常青词是满序列。判据:点数 `<= 5` 且末值 `>= 20 万`
(20 万取自实测分位 p25=28 万,再往下多是长尾词条)。

### 1.2 之前的「门槛 275 倍」结论已被订正

上一版写的是「长尾热点**永远**只能定向查」——**过强了**:

| | 全局榜 `dw=168` | 截图那三个词(定向查) | 1 小时榜 `dw=1` |
|---|---|---|---|
| 门槛 | 第 49 名 = **2.1 亿** | 76.5 万 ~ 724.7 万 | **6 万 ~ 4.7 亿**(p25=28 万) |
| 无种子能拿到吗 | 只拿到亿级 | 拿不到 | **能,50 条一次** |

真正的区别不是「能不能拿到」,而是**「拿到的时机」**:高窗口给**累计量**,
1 小时榜给**当下在冲的词**。后者才是新事件。

## 二、能活多久:**当天的热点必须当天跟**

按峰值 ≥5×基线、≥20 万算一个爆点(94 个),次日相对峰值:

| 次日/峰值 | 占比 |
|---|---|
| ≥0.8(还在烧) | **38%** |
| 0.4~0.8(半衰) | 31% |
| <0.4(凉了) | **31%** |

按「爆发后第几天」看次日仍 ≥50% 峰值的比例:第 0 天 63%(n=172)/ 第 1 天 48%(n=92)/
第 2 天 41%(n=49)/ 第 3 天 66%(n=32)/ 第 4 天 48%(n=21)。≥5 天样本太少,不下结论。

⇒ 作业 4 小时一轮,**第二轮跑的时候约 1/3 已经凉了**。

## 三、值不值得跟:**在抖音上没人推网盘**

对 7 个爆发词(`小小甄选`/`水老鼠`/`覆面系`/`玲玲夫妇`/`爆炸桃`/`黑白覆面`/`小小猪`)
各取 13~14 条抖音搜索结果:

- 带网盘链:**0 条**
- 标题带资源语义(网盘/链接/全集/口令/迅雷/夸克…):**0~1 条**(那 1 条还是「摘桃子」)

对照库里真出货的词:`白泽的梦` 100%、`天晴宝箱` 100%、`咐置` 32% —— 全是**资源名**。
`runs` 里 11 轮大瓜轮**全部 `外部命中0/产出0`**,搜回来的是漫剧/游戏/问卷。

⇒ **热点词喂 `demand_watch`(找名字),不喂 `douyin_leads`(找盘链)。**

⚠️ 而且即便喂 `demand_watch`,抽出来的也常是泛词:实测 `黑白覆面塌` 两条视频各拉 3 页评论,
`frequent_entities` 过闸后给出的是 `万圣节`/`种感觉`/`互联网`/`中国`/`帽檐`/`帽子`
—— **没有名字**。纯八卦的评论区是「议论」,不是「报名字」。这条链路的真实产出率**仍待观察**。

## 四、测不出来的三条(如实写下,别再重复试)

**1. 突增倍数预测不了明天**:按「末日/前段中位数」分桶,次日再翻倍率 ——

| 倍数档 | 次日再翻倍率 | n |
|---|---|---|
| 0~2 | 5.2% | 4238 |
| 2~5 | 5.8% | 449 |
| 5~10 | 3.3% | 121 |
| 10~30 | **13.5%** | 126 |
| 30~100 | 8.3% | 72 |
| >100 | 7.5% | 80 |

基线 5.2%,区分度约 2 倍且**非单调**。典型误判:`爆炸桃` 124 倍,实际是**水果**。

**2. 形态预测不了未来**:平稳(n=3524)+2 天翻倍率 14.1%/+3 天 16.7%;
波动 13.1%/17.8%;爬升 15.6%/21.2%;阶跃 12.8%/19.1% —— **四类几乎一样**。

**3. 跨种子共振 = 0**:359 个词里被 ≥2 个不同种子同时返回的有 **0 个**。
「多垂类同时抬头 = 大热点」这个直觉,**在这批样本上不成立**。

⇒ `hot_cycle` **不输出任何预测值**。它输出**已经发生、可核查的事实**
(什么时候上榜、现在多大量、出自哪条通路),排序只靠事实。

## 五、落地在哪

| 位置 | 作用 |
|---|---|
| `app/services/hot_cycle.py` | 判据本体:`board_words`(无种子,主通路)、`emerging`(种子族,补位)、`hot_video_seeds`(取词入口) |
| `demand_watch.source_videos()` 的「①.5」 | 把取到的热点词丢给 `dps.search` 找视频,按评论数过滤后进扫评论队列 |
| `DEMAND_HOT_VIDEOS` | 每轮拿几个热点词搜视频,默认 **2**;设 0 关闭 |

⚠️ 顺序**必须**在「同款作者新作品」之前 —— 作者分支会占满 `need`,热点就永远轮不上
(与 2026-11-08 那个 `return` 把热榜词吞掉的 bug 是同一形状)。

⚠️ `hot_words`(内容词榜)虽然一次能回 200 条,但**末点滞后一天以上**,
不能拿来判「今天首现」;只有搜索榜的 `date_window=1` 是小时级。

## 六、形态词探针:**榜单盲区里的新事件**(2026-11-10 实测)

### 6.1 起因:一个真热点,两条现成通路都抓不到

用户点名核验的「**只忍五次**」:

| 事实 | 实测值 |
|---|---|
| 近 1 小时搜索量 | **16.3 万 / 15.8 万 / 14.7 万**(三个变体) |
| 3001 榜第 50 名分数线 | **217 万** ⇒ 差 **13 倍**,进不了榜 |
| 3002 榜第 50 名分数线 | 38.9 万 ⇒ 仍进不了 |
| 搜索榜翻到第 **60 页** | 仍找不到;而第 8 页分数线已降到 6.8 万(**比它还低**) |
| 热点宝 `dw=168` 有它吗 | 有(`只忍老板五次直播泼粪后续` 737 万)⇒ **只是当下不在榜** |
| 评论判据 | 4 条视频各 40 条评论,整条 `1` 0~2、求 0~4、密度 0~10%(低于 0.1 门槛) |

⇒ **榜单是策展式的,新事件进不去;翻页/调阈值都救不了。**
但 `hot_search(keyword=…)` 定向查询走的是**全量词库**,不是榜单 —— 这是缺口所在。

### 6.2 解法:用「事件语法壳子」而不是固定词条

用户口径:「每个词条都不一样,没办法给固定词条」。事件名确实任意,但它**必须被填进
固定的几种壳子**才能被搜索和传播:

```
后续 · 回应 · 通报 · 事件 · 离职 · 处罚 · 被罚 · 警方 · 最新 · 完整版 · 来龙去脉 · 原因
```

⇒ 12 个词 × 1 次请求(`limit=50, date_window=1, sub_type=3001`),

| 指标 | 实测值 |
|---|---|
| 非满序列候选 | **275** 个(本次复跑 107~120) |
| 常青词被挡掉(24 点满序列) | **177** 个 |
| 峰值 ≥15 万 | **117** 个 |
| 峰值 <1 万(长尾噪音) | 仅 10 个 |
| 其中含目标 | `彻底疯狂泼粪离职事件回放`(270 万,原作者)、`老板处理泼粪事件方法`、`泼粪离职事件忍5次视频` |

### 6.3 三条判据(缺一不可)

| 判据 | 值 | 为什么 |
|---|---|---|
| 序列点数 `< 23` | `CARRIER_FULL_POINTS` | 满 24 点是常青词(`财经直播`/`东方甄选直播间`/`台球直播` 实测全是 24 点);目标 `只忍老板五次直播视频` 是 **13** 点、`医院老奶奶被打后续` 是 **3** 点。⚠️ **不能用榜单那条 `FRESH_POINTS=5`** —— 只忍 13 点会被直接漏掉 |
| 峰值 `>= 15 万` | `CARRIER_MIN_PEAK` | 再往下是小事件的不同说法 |
| 词里含形态词本身 | 硬校验 | 接口声称按 keyword 过滤,但**不假定它一定照做**(否则一次探针就把整张榜塞进来) |

### 6.4 归并:同一事件的多种说法必须并,且**差分要按组**

实测只忍一族有 10 种说法,两两 Jaccard(二元组)校准:

| 一对 | 相似度 |
|---|---|
| `泼粪离职事件处理` ~ `…处理方法` | **0.78** |
| `泼粪离职事件处理` ~ `…忍5次视频` | 0.42 |
| `泼粪离职事件处理` ~ `彻底疯狂…回放` | **0.385** |
| `老板骂我5次就离职后续` ~ `…直播回放` | **0.571** |
| `泼粪离职事件处理` ~ `老板骂我5次就离职后续`(不同事件) | 0.062 |
| `泼粪离职事件处理` ~ `只忍老板五次直播视频`(不同事件) | 0.000 |

⇒ 取 **0.3**,并查集传递闭包串起整族。

⚠️ **差分必须按事件组做**(这条是后来发现的真 bug):若只把「代表词」记进库,
明天另一种说法(比如 `…直播回放` 峰值涨过 `…后续`)就会被判成「新事件」再推一次。
所以:组里**任一说法**见过 ⇒ **整组**算旧;记账时**整组所有说法**都写进 `hot_word_seen`。

⚠️ 已知副作用(可接受):`常州地震官方通报` ~ `泰州地震官方通报` = 0.75、
`乐平/弋阳/江西巨响官方通报` = 0.556 会被并成一条。我们要的是**能去抖音搜的搜索词**,
江苏多地地震 / 江西多地巨响本就是同一轮新闻。

### 6.5 关于「剧情/短剧词混进来」

探针的 top 里确实混着 `猪八戒苏醒后续`/`蛇妖偷吃鸡蛋后续`/`青黛后续完结大结局`。
**但实测结论是不要按题材过滤**:

| 证据 | 结果 |
|---|---|
| 新闻词(`中方回应黄乐`/`滑县婚礼照搬事件`)的评论 | 只有「蹲新闻本体」,**资源名 0 个** |
| 剧情词的评论 | 至少有人在问「求背景音乐」这类 |
| 库内真正产出过的名字 | `嫁金钗`/`恶女得宠`/`白泽的梦`/`第十七个夏天` —— **全是短剧/小说名** |
| 用户五方向 | 影视、漫剧本来就是重点方向 |

⇒ 热点宝返回体只有 `key_word/search_score/trends` 三个字段,**没有内容字段**可用于
离线区分新闻与剧情;而下游(评论求资源)的判据会自动只留下有资源的那批。
**结论:不过滤,交给评论判据筛。**

### 6.6 落地

| 位置 | 作用 |
|---|---|
| `hot_cycle.carrier_words()` | 探针本体,**不读不写库**(纯函数可测) |
| `hot_cycle._group_events()` | 分组(差分的底座),`_merge_events()` 只是取每组的 `g[0]` |
| `hot_cycle.new_hot_words()` | 带差分取词;**自己开短会话**记账,写完立刻提交关闭 |
| `hot_cycle.seen_before/remember/prune_seen` | `hot_word_seen` 表的读写,保留 14 天 |
| `demand_watch.source_videos()` ④ | 调用 `new_hot_words`(替换原来的 `hot_video_seeds`) |
| 降级链 | 探针 → `board_words`(1 小时榜)→ `emerging`(种子族) |

配置项(`config/settings.py`):

| 配置 | 默认 | 含义 |
|---|---|---|
| `hot_carrier_enabled` | `True` | 关掉就退回 1 小时榜那条路 |
| `hot_carrier_full_points` | 23 | 点数 < 它才算新起量 |
| `hot_carrier_min_peak` | 150000 | 峰值门槛 |
| `hot_carrier_top_n` | 5 | 每轮最多交几个归并后的事件 |
| `hot_carrier_merge_jaccard` | 0.3 | 归并阈值 |
| `hot_word_keep_days` | 14 | `hot_word_seen` 保留天数 |

⚠️ **写锁纪律**:`new_hot_words` 取数(12 个 HTTP)在**开会话之前**就做完;
`session=None` 时自己开短会话,`commit()` + `close()` 只锁几毫秒,
**绝不借 `source_videos()` 的 `db`** —— 那个会话后面还要跨搜索/评论那些慢活。
