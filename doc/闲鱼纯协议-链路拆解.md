# 闲鱼纯协议:链路拆解与自修指南

> 2026-10-08 建。姊妹篇:`小红书纯协议-链路拆解.md`、`抖音纯协议-链路拆解.md`。
> **这篇的核心是一句话**:`RGV587_ERROR::哎哟喂,被挤爆啦` 跟账号、出口、TLS、请求头**都无关**,
> **卡的是 cookie 那一份**。我们为此绕了两年。

---

## 0. 结论(时间紧只看这里)

1. **纯协议可用**,`XianyuClient` **一行代码都不用改** —— 换一份**完整的 cookie jar** 就行。
2. 实测:3/3 关键词、每个约 **0.35 秒**(浏览器那条要 10~20 秒,还偶发 `TargetClosedError`)。
3. **搜索与深采(详情)两个接口都验过了**。
4. 采集路径已改成**协议优先、浏览器兜底**;开关 `XIANYU_PREFER_PROTOCOL`。

⚠️ **还没验的**(别当成已完成):只验了**首屏**;翻页未验;整套 cookie 的**有效期**未知;
连发多少会再触发风控未知。

## 1. 链路长什么样

```
tools/xianyu_export_cookie.py      ← 从浏览器档案导出**整套 jar** → 加密 cookie 库(平台 goofish)
        │
        ▼
app/services/tenant.py  run_xianyu()
        │  客户端选择:`tenant_base.pick_xianyu_client()`
        │     ① 协议优先(约 0.35 秒/词)
        │     ② 失败 → 回落浏览器(`_collect_hot_with_fallback`,重跑且**留痕**)
        ▼
app/services/xianyu.py  XianyuClient      ← 签名 / 令牌刷新 / 错误分类,本来就写好了
        │
        ▼
POST https://h5api.m.goofish.com/h5/mtop.taobao.idlemtopsearch.pc.search/1.0/
        │
        ▼
app/services/xianyu_analytics.py  run_xianyu_deep()   ← 深采(详情/想要数)**同一个选路函数**
```

★ **搜索与深采必须用同一条路**。2026-10-03 就是因为两边分叉(搜索走浏览器、深采走协议),
行情(想要数/收藏/出单)一直卡在风控上,而症状看起来像"接口没数据"。
现在两边共用 `tenant_base.pick_xianyu_client`,规则只有一处。

## 2. 接口合同

**端点**:`POST https://h5api.m.goofish.com/h5/mtop.taobao.idlemtopsearch.pc.search/1.0/`

**查询参数(12 个,一个不多一个不少 —— 抓包实测)**:

| 参数 | 说明 |
|---|---|
| `jsv` | `2.7.2` |
| `appKey` | **`34839810`** |
| `t` | 毫秒时间戳 |
| `sign` | `md5(token & t & appKey & data)`,token = `_m_h5_tk` 里 `_` 之前那段 |
| `v` / `type` / `dataType` / `accountSite` / `timeout` / `api` / `sessionOption` / `spm_cnt` | 固定值,见 `xianyu.py` |

**⚠️ body 是 form 编码**:`data=<urlencode 过的 JSON>`,**不是裸 JSON**。
`json.loads(body)` 能过但顶层字段是空的 —— 我第一次就栽在这,又包了一层
`data={"data": body}`,被回 `FAIL_BIZ_COMMON_PARAM_ILLEGAL::闲鱼太累了休息一会吧`。

**请求头 —— 只有两个**:
```
Accept: application/json
Content-type: application/x-www-form-urlencoded
```
★ 抓包实测页面**没有带任何自定义头**。所以"我们少了某个头"这个方向**是死的**,
别再往那儿查。

## 3. ★ 真正的关卡:cookie jar

页面发出去的是**整套 jar**(16~18 项),而我们当年只贴了"登录三件套"。关键在这几组:

| 组 | 项 | 作用 |
|---|---|---|
| 登录态核心 | `unb`、`cookie2` | 缺任一必 `TOKEN_ILLEGAL`(代码里有校验) |
| **风控 SDK** | **`sgcookie`、`tfstk`、`_tb_token_`、`_hvn_lgc_`、`havana_lgc2_77`** | ★ **阿里 Havana 风控 SDK 发的** —— 被校验的就是它们 |
| mtop 令牌 | `_m_h5_tk`、`_m_h5_tk_enc` | 短效,采集器首屏会自己从网关拿 |

**判据是控制变量出来的**:

| 变量 | 结果 |
|---|---|
| 匿名(只有 `cna` 等 5 项) | ❌ `RGV587_ERROR::被挤爆啦` |
| 匿名 + 照抄开源客户端(httpx / 老 UA / 无 Origin) | ❌ 同样被挤爆 |
| **整套 jar + 普通 `requests`(连 TLS 指纹都不伪造)** | ✅ `SUCCESS::调用成功` |
| 整套 jar + `curl_cffi` | ✅ 同样成功 |

⇒ 与账号无关、与出口无关、与 TLS 无关。**只与 cookie 有关。**

## 4. 凭据从哪来

```bash
python tools/xianyu_export_cookie.py --check   # 只看关键项齐不齐,不写库
python tools/xianyu_export_cookie.py           # 导出进加密库(用户 1,平台 goofish)
```

⚠️ **别再手工从浏览器 Network 里抄 Cookie 了** —— 抄不全,而且**没人知道漏了哪一项**。
这次绕两年,根源就是这个动作。

**两个已踩的坑**:

1. **必须先访问一次首页**。只开浏览器不导航时 `ctx.cookies()` 只回 **13** 项,
   **缺 `cookie2` 和 `_tb_token_`**;页面加载过之后才变成 16~18 项。
   所以导出工具里的 `goto` 不是"顺手逛逛",是**必要条件**。
2. **别去杀占着档案的浏览器**:那是生产在用的那个(进程内单例、闲着也留着)。
   等它闲置自关(`XIANYU_BROWSER_IDLE_CLOSE_SEC`,默认 900 秒)。

## 5. 踩过的坑(2026-10-08,全部真踩)

### 坑 1:★ 两年的错误归因 —— "账号级限流"
我们一直写 `RGV587 是账号级限流`(依据:"换手机热点出口也没用、请求量只有 6 次/小时,
所以既不是 IP 也不是频率")。**这个归因是错的** —— 匿名请求(压根没有账号)照样被挤爆。
它会把后来的人引向"换个号/换份 Cookie 就好了",而那不是解法。

### 坑 2:协议相对 URL 让重放"看起来被拒"
页面用 `//h5api.m.goofish.com/...`(协议相对),`urlparse` 给的 scheme 是**空串**,
拼成 `://host` ⇒ 两次重放全报 `InvalidSchema` / `InvalidURL`。
**看起来像被拒,其实是自己拼错了 URL。** 这类"自己造的失败"最容易被误读成平台行为。

### 坑 3:form body 被包了两层
见 §2。注意它回的是 `FAIL_BIZ_COMMON_PARAM_ILLEGAL::闲鱼太累了休息一会吧`
—— ⚠️ **那已经不是 `RGV587` 了**,说明风控关卡当时**已经过了**,只是参数不对。

### 坑 4:深采与搜索分叉(2026-10-03)
见 §1。规则现在只有一处(`pick_xianyu_client`),并有测试钉住。

### 坑 5:浏览器路自己的偶发失败
`TargetClosedError: BrowserType.launch_persistent_context`(2026-10-08 00:43 实测一次)
会让**整轮**失败。换成协议后这类失败一并消失。

## 6. 出问题时的排查顺序(照这个走)

```
闲鱼采集没数据
  ├─ 运行记录 `[协议]` + 0 条      → 可能真没货;换个词再看
  ├─ 运行记录 `[浏览器兜底]`       → **协议失败了**,日志里有 `闲鱼纯协议失败(kind)`
  │      └─ kind=XianyuRateLimit(被挤爆) → **cookie 过期了** → 重跑导出工具
  │      └─ kind=XianyuVerify(滑块)      → 冷却;别连发
  │      └─ kind=XianyuCookieExpired     → 令牌坏了 → 重跑导出工具
  ├─ `cookie_incomplete(缺 unb/cookie2)` → 库里那份 jar 不完整 → 重跑导出工具
  └─ 详情/行情一直不更新           → 检查**深采是否与搜索同路**(§1)
```

**别做的事**:改签名(= 它本来是对的)、换 UA、换出口、反复重试。
§3 那张表已经把这四条逐一排除过了。

## 7. 现状与待办

  (选路不走协议 / 回落被删 / 深采退回老规则 —— 三种改动都会被测试抓到)。
