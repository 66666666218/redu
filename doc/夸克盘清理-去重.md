# 夸克盘清理:跨目录重复 + 别人的引流文件

> 2026-10-08 建,2026-10-10 补「多轮收敛」。代码:`app/services/quark_dup.py`(判据)+
> `app/services/quark_dup_cache.py`(扫描快照)+ `scripts/quark_dup_{report,apply}.py`。

## 要解决什么

盘上有**一堆「家」目录**:`redian监听`、`redian监听_0913`、`redian监听_0920`…(2026-10-10 实测 **19 个**,
其中 6 个带 `_2` 后缀 —— 同一天建了两次)。每换一次家,**同一个资源的文件就又存一份**
(查重是按目录做的,换了目录就一个都认不出来)。

⇒ 要做的:**跨家去重**(同名 + 同大小视为同一份,留**最新在用的那个家**里的那份),
外加清掉**别人的引流文件**(导流到别的网盘/加群的广告文件、二维码…)。

## 怎么用

```bash
python scripts/quark_dup_report.py            # 只读,出计划(默认只清 10 月的账)
python scripts/quark_dup_report.py 10         # 同上,显式指定 MMDD 前缀
python scripts/quark_dup_apply.py             # 再看一遍计划(dry-run,一个字节都不删)
python scripts/quark_dup_apply.py --yes       # 真删 —— **进回收站**,可捞回
python scripts/quark_dup_apply.py --yes --max 5   # 先小批试
```

## 判据(在 `classify()` 里,是纯函数,可离线测)

| 情况 | 处理 |
|---|---|
| 名字命中**强模式**(名字本身就是"下载/加群指令") | **删** |
| 名字命中**弱模式**(含 必看/教程/注意/截图…) | **只报告,不删** —— 见下 |
| 跨 **≥2 个家**、且 ≥1 MiB | **删**,留**最新在用的那个家**里的那份 |
| 我方**已发出的分享链**指着的 fid / 名字 | **永不删**(删了 = 已发出的链接变"已失效") |
| 我们的宣传简介 | **永不删** |

⚠️ **弱模式为什么只报告**:它在这份盘上**逻辑失效** —— 同一份资源本来就被重复存到多个家,
于是包里几乎每个文件都"横跨多个家",那条判据退化成"名字里带『注意』就删"。
实测误判过 `高中英语151组最容易拼错的单词，考场上一定要注意！.docx` 这类**真学习资料**,
而这一类总共只有 269 MiB —— **省不到空间却会误删资源** ⇒ 降级成"待确认",由人判。

## 扫描要多久(2026-10-10 实测)

**一个家 ≈ 728 次 `list_dir` ≈ 10.7 分钟**(`list_dir` 每次约 1.2 秒)。
19 个家全扫完 ≈ **3.4 小时**。而 `QUARK_CLEANUP_BUDGET` 默认 2500
⇒ **一轮只能扫完约 3 个家**。

## ★ 多轮收敛(2026-10-10 新增)

**以前**:扫不完 ⇒ 什么都不留 ⇒ 下一轮又从头发起,永远卡在同一处。

**现在**:扫完的家写进快照 `data/quark_dup_cache.json`(原子替换),
下一轮**直接复用**;没排上的家记进 `remaining_homes`,**接着扫**。
⇒ 重复跑同一条命令即可,6~7 轮收敛完 19 个家。

```

   ⏳ 还差 4 个家没扫(其中 0 个扫了一半):redian监听_0928、…
```

### 安全边界(这份快照会参与"删文件"的判据,所以每条都是故意设计的)

1. **TTL(默认 8 小时)**:过期的家**重扫**,不吃旧数据;
2. **`complete` 要求"所有家都有有效数据"且"没撞预算"**。只要有一个家没扫到,
   重复数就会**算少** ⇒ "只在一个家里"变成假判断 ⇒ **执行器默认拒绝删**;
3. ⚠️ **危险方向**:快照说"某文件在 A、B 两家都有",而其实 A 那份已经没了 ⇒ 会删掉**唯一的副本**。
   兜底两层:① TTL 限窗口;② **删除永远进回收站**(`to_recycle=True`);
4. **删过东西的家立刻作废**(`drop_homes`)—— 那些家的内容变了,旧快照不再代表现状;
5. **残缺数据是安全的**:漏扫只会让重复看起来更少 ⇒ 倾向于**不删**(漏删,不是误删)。

### `--depth` 怎么选

`depth=2` 是默认,**别改成 1 来"加速"**:同一个家实测 `depth=1` 只看到 **491** 个文件,
`depth=2` 看到 **4953** 个 —— **差 10 倍**,因为资源多在 `家/资源名/子目录/文件` 这一层。
漏扫只会漏删(安全),但清不干净。**正路是保持 depth=2 + 多跑几轮。**

## ⚠️ 2026-10-10 踩到的一个**危险不一致**(已修)

`report` 与 `apply` 两个脚本的**默认清理范围原本不一样**:

| 脚本 | 原本的 `mmdd_prefix` | 含义 |
|---|---|---|
| `quark_dup_report.py 10` | `"10"` | 只清 **10 月**的家 |
| `quark_dup_apply.py` | **`""`(没有这个参数)** | **所有月份** |

后果:同一次清理,**报告说 102 个 / 3.66 GiB,执行却删了 7735 个 / 264 GiB** ——
差的 70 倍就是"10 月"与"全部月份"。

**修法**:`apply` 加上 `--month`(默认 `"10"`,与 report 同口径),并在执行时**大声打印范围**。
**教训**:"用来判风险的报告"和"真正动手的执行器"**必须同范围** ——
否则人按报告做的判断,执行时全不作数。这是比"某个判据写错"更隐蔽的一类错,
因为它两边**各自都是对的**。
