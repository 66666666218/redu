# 百度盘的去重(只识别 + 清单,**默认不删**)

> 2026-10-16 建立。三盘里只有百度这半边没接"自动清理" —— 原因见下。

## 为什么百度**不自动删**

**百度没有回收站,删了捞不回来。** `baidupan_transfer.delete_paths` 的文档里就写着
「调用方必须自己确认路径」。夸克/迅雷那两盘删错还能从回收站捡回来,**百度不行** ——
风险不对称,所以用户 2026-10-16 拍板:**先做识别 + 清单,删除开关等看过真实清单再决定**。

⚠️ 所以 `scripts/baidu_dedupe.py` **没有 `--apply`,而且不是忘了** ——
与夸克那边"先开 `DRY_RUN` 跑几轮再关"同一条纪律。

## 判据(实测订正过一次,别想当然)

**同一个基名 + 同一个大小**出现 ≥2 次 = 重复。基名 = 剥掉自动改名后缀:
`(1)`(夸克形态)与 `_<≥6位数字>`(**百度形态**)。

⚠️⚠️ **不要求"跨目录"** —— 这是那次订正的正身:
百度重复保存同一份资源时,是**在同一个目录里**给它加 `_<数字>` 尾巴:

```
/来自资源批量转存/137号案件.apk               95433288
/来自资源批量转存/137号案件_1011213845.apk     95433288
/来自资源批量转存/137号案件_1011214401.apk     95433288
```

第一版照搬夸克那条「必须跨目录」的判据(夸克是**跨家**的形态)⇒
**扫了 9950 个文件却报「重复 0 组」**,而肉眼一看就有好几组。

- ⚠️ **只同名不够**(同名不同大小是两份不同的东西);⚠️ **只同大小也不够**。
- ⚠️ `_123` 这种**短**数字后缀**不剥**(可能是文件名本身),宁少判一组。
- ⚠️ **宣传简介必须排除**:它被设计成"塞进每个资源目录",天然同名同大小 ——
  不排除的话它会是清单里最大的一坨,而删它等于把功能砍了(见 `doc/三盘宣传简介.md`)。
- 留哪份:留**名字就等于基名**的那份(没被加尾巴的)。

## 实测(2026-10-16,只读扫描)

```
扫描根 /        扫 9950 个文件 / 102 个目录
**重复 186 组 / 多出 1398 份 / 106.40 GiB**(且**没列完**,见下)

老舅.apk            ×110 份     ← 同一份被反复转存了 110 次
人之初.apk          ×49
江西智慧教育平台.apk ×33
内蒙教育云…apk       ×30
```

真正的落点是 **`/来自资源批量转存`**(盘商自己的"批量转存"目录,9950 个文件/1086 GiB);
根目录下还散着 **51 个**同族目录(基本是空壳/实验残留:`_限流实验`、`测试组2`、`zz建目录测试`)——
与夸克那边「保存目录会漂」是同一个形态,所以默认**从根目录扫**、别写死某一个家。

## 两个必须如实报出来的边界(静默截断 = 假结论)

1. **盘商翻页上限**:`BaiduPanClient.list_dir` 内部**翻页到 10000 就停**
   (`while start < 10000`)⇒ 拿到**正好 10000 条**意味着那个目录**还没列完**。
   实测那个目录就是这样 ⇒ 上面的 186 组/106 GiB **是下界,不是全部**。
2. **列不动的目录 ≠ 空目录**:第一版的默认根(`/redian百度转存`)**在盘里根本不存在**,
   `list_dir` 抛 `errno=-9`,而代码把异常吞了 ⇒ 报告写着「重复 0 组(扫 0 个文件)」——
   **一个目录都没列成,却像个干净的结论**。现在 `walk` 会把它记进 `errors`。

## 怎么跑 / 清单在哪

```bash
python scripts/baidu_dedupe.py            # 扫一遍、打清单、写 data/pan_dedupe_baidu.json(只读)
python scripts/baidu_dedupe.py --json     # 只打 JSON
```

**每天 04:20 的自动清理**也会顺带跑一次(`pan_auto_clean.report_baidu`),
把摘要写进 `runs.detail`(「跨目录重复 N 组/多出 M 份(X GiB)」+ 清单路径)。
⚠️ 那一条**只报告、不删**,与本文开头那条边界一致。

### 清单路径与「被测试覆盖」(2026-10-19)

- 路径由 `PAN_AUTO_CLEAN_BAIDU_REPORT_PATH` 决定(默认仍是 `data/pan_dedupe_baidu.json`)。
- ⚠️ **真实事故**:`tests/test_baidu_dup.py` 原来调用真实的 `report_baidu()`,
  而路径写死 `data/...` ⇒ 跑一次测试就把**生产清单覆盖成 `dup0.apk / 100 字节`**
  (2026-10-18 23:40 实测)。现在测试**显式传临时路径**,并有一条回归守卫断言
  生产清单的 mtime 不变。
- **每天 05:10 的网盘自检**会检查这份清单:不存在 / 超过 48h / 内容是 `root="/"` +
  `dupN` 形状的测试数据 ⇒ 推管理群并提示重扫
  (`python scripts/baidu_dedupe.py`)。
