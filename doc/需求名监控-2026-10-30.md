# 评论区「在求什么」监控(2026-10-30)

> 用户口径:「帮我监控一些**评论区都在求的大瓜名称**…只需要**监控名称**就行,
> 不用保存到网盘,抖音和小红书是最容易的…有些小红书是有吃瓜群的。」

## 一、能不能做到(先给结论,再给证据)

| 环节 | 结论 | 证据(2026-10-30 实测) |
|---|---|---|
| 抖音拉评论 | ✅ **能** | `/aweme/v1/web/comment/list/` **必须带 `a_bogus`**:不带回**空体**,带签名 200 + 20 条(同一条视频、同一枚 cookie 的对照实验) |
| 从评论抽名字 | ✅ **能**(对用户给的 8 个样例全中) | `《狗爹和小桃》`/`《兄妹蕉谈》`/`《Alli Skye》`/`《pupu噗噗》` 全部抽出;「求《兔兔图图》全集」判为**需求**而不是普通提及 |
| 名字来得够不够 | ❌ **取决于素材** | 近 7 天线索里抽 4 条视频 × 20 条评论:**「求」字样 0 条**。短剧类线索的评论区是**剧情讨论**(「这女的叫什么」都少),不是求资源 |
| 小红书 | ⚠️ 未做 | 评论要走登录态 + 页面渲染(协议路 `461`/`300011` 风险高、会话几分钟就死),见 `xhs-461-solved-by-page-render` |

**一句话**:管道通了,**素材决定产出**。现在这套在抖音短剧线索上产不出名字榜;
换成"评论区真在求"的那类视频(用户给的那类)才有量。

## 二、这一版做了什么

`app/services/demand_watch.py` → 表 `demand_names` → 飞书卡 `🔍 评论区在求的名字 · 抖音`

1. **素材**(`source_videos`):优先我们自己收的推广视频
   (`douyin_leads` 近 7 天)→ 对标号带盘作品(`douyin_peer_works`)→ 搜索补位。
   ⚠️ **不再"搜 `吃瓜` 就开扫"**:实跑抓回来的是**亲子起名**和**外卖折扣群**,
   抽出来「姓龙比较适合」「8折外卖」—— 真需求,但不是这一类。
2. **拉评论**:每视频 `demand_comment_pages` 页 × 20 条,顺带取**回复预览**
   (`reply_comment`)—— 「这女的叫什么」的答案通常在回复里。
3. **抽名字**(`extract_names`):书名号优先;其次「求/想要/谁有/在哪看…」后面那段。
   **求 vs 提及分开计**:只提到不算需求(否则榜单会变成"热门",不是"被求")。
4. **过滤**(实测长出来的,不是拍脑袋):
   - `求个真实有效的资源` → 抽出「真实有效」 ⇒ 加**半句话黑名单**(一下/分享/有效/谢谢…);
   - `现在父母起名字…别人问你孙子你爷爷叫什么` → 抽出「别人问你孙子你爷爷」 ⇒ 加**代词黑名单**(你/我/他/她…);
   - `这女的叫什么` → 抽出「这女」 ⇒ 加**指示代词**(这/那) + 未加书名号的候选**限 12 字**。
5. **入库/推送**:`demand_names` 累计 `demand_hits`/`mention_hits`/`video_hits`,
   `samples` 留**评论原文 + 视频链接**(名字必须能回溯)。
   推送门槛 `demand_min_hits`(默认 2),**48 小时冷却** —— 作业 4 小时一轮,不冷却就是一天推 6 次。
6. **0 产出要留痕**:扫了视频却没名字 ⇒ `runs` 记 `partial`,明细写
   `求N(无名)`。这个数是判断「素材对不对」的唯一证据:
   `>0` = 有人求但没说出名字;`=0` = 这批评论区压根不是求资源的场景。

## 三、配置(`.env`)

| 键 | 默认 | 说明 |
|---|---|---|
| `DEMAND_WATCH_ENABLED` | true | 总开关 |
| `DEMAND_SOURCE_DAYS` | 7 | 素材取近几天 |
| `DEMAND_SEED_WORDS` | 空 | **补充**搜索词(**留空 = 不搜**)。填**具体名字**才有意义(实测 `狗爹和小桃` 能搜到同类视频) |
| `DEMAND_MAX_VIDEOS` | 6 | 每轮扫几个视频(额度按它线性增长) |
| `DEMAND_COMMENT_PAGES` | 2 | 每视频翻几页评论 |
| `DEMAND_MIN_HITS` | 2 | 被求几次才推 |
| `DEMAND_PUSH_COOLDOWN_HOURS` | 48 | 同名字重推冷却 |
| `DEMAND_WATCH_CRON` | `50 */4 * * *` | 与 `douyin_leads`(`:10 */4`)错开 40 分钟 |

## 四、下一步需要用户给的东西

**素材源才是瓶颈**。要让它出量,请给 2~3 个**评论区确实在求**的:

- 抖音**账号主页链接**或**视频链接**(那种一打开评论就是「求《X》全集」的);
- 小红书同理(另配 CDP 路,风险单独评估)。

拿到后把它们加成固定素材源(与对标号同一套机制),这个模块的产出才有意义。

## 五、名字取自**作品名**,热度看**求 + 扣1**(2026-10-30 追加)

用户口径:「**基本上作品名都有资源名**,判断是根据作品里面的**求**和**1**来判断火爆程度」。

于是口径拆成两半:

| 维度 | 从哪里取 | 字段 |
|---|---|---|
| **名字** | **作品标题里的书名号**(`《…》`) | `title_hits`(出自几个作品标题) |
| **有人求** | 评论里的「求/谁有/在哪看…」 | `demand_hits` |
| **被勾住** | 评论里**整条就是 `1`**(「扣1看完整版」的跟帖) | `ones_hits` |

- 只认**整条**是 `1`/`扣1`/`1111`,**不做子串匹配**(「第1集」里的 1 不算);
- 一条视频的「扣1」热度归给**这条视频标题里的名字**(整条视频级别,不是单条评论);
- 上卡条件(满足其一):`demand_hits ≥ DEMAND_MIN_HITS`(默认 2)**或**
  `ones_hits ≥ DEMAND_MIN_ONES`(默认 20);
- 卡片一行:`名字 — 求 N 次 · 扣1 M 条 · 提及 K 次`。

**当前实测**:作品名抽取出得来(试跑 4 条视频拿到 `反差直男`/`胖妞出嫁`/`港枭风云`);
但这 4 条的评论里 **求 0、扣1 0** —— 再次说明瓶颈在**素材**,不在管道。

### 5.1 参考作品名当**素材种子**(2026-10-30 追加)

用户:「**我上个对话给你的就是参考作品**」⇒ 那几个名字(狗爹和小桃、小小绘、pupu噗噗、
兄妹蕉谈、兔兔图图、sunny水水水、Alli Skye、香香公主与爱犬金毛、兽人与人类的禁忌羁绊)
写进 `.env` 的 `DEMAND_SEED_WORDS`,作为**素材源**按名字搜同款视频。

- **每轮只搜 3 个、轮着来**(`DEMAND_SEEDS_PER_ROUND`):抖音连发会进「空成功」限流(~35 分钟自愈);
- 参考作品只占**一半名额**,另一半留给库内推广线索 —— 因为参考作品的标题是"标签流",
  **没有书名号**,名字抽不出来;
- 游标存 `system_config:demand_seed_cursor`,重启不丢。

### 5.2 标签**不算**名字(实跑后改回来)

试过把 `#标签` 也当名字,抽出来的是 `青筋`/`小桃`/`锐评`/`交流`/`vlog日常`/
`vlog十亿流量扶持计划` —— 标签是**描述词**,放进榜里比没名字更糟。名字只认 `《》`。

### 5.3 「1」拿不到,用评论总量当火爆度

实测:一条 **17,961 条评论**的视频,按热度排序的前 3 页(60 条)里 **0 条「1」**
—— 「扣1」的跟帖都是零赞,排序后沉在很后面,翻不到。
所以 `ones_hits` 只能作辅助;新增 `heat_score` = 这些作品的**评论总数之和**,
卡片上显示为「评论热度」—— 这是**可得**的火爆度。

## 六、「最新的大瓜」:顺参考作品找同款账号(2026-10-30)

用户口径:「**根据这些去找最新的大瓜**」。

链路:参考作品名(种子)→ 抖音搜索 → 搜到的**作者** → 作者主页作品接口
`/aweme/v1/web/aweme/post/`(同样**必须带 `a_bogus`**,实测 200 + 17 条,
每条带 `create_time`/`desc`)→ 只要最近 `DEMAND_LATEST_DAYS`(默认 3)天的 →
按发布时间倒序 → 推「⏰ 最新大瓜 · 抖音」卡(时间 + 作者 + 标题,点标题看原视频)。

**两道闸门(都是实跑撞出来的)**:

1. **相关性**:抖音搜索很"松" —— 种子 `兔兔图图` 会返回儿童动画号,跟着它们拉主页拿到的是
   电影解说/美食。所以要求**该号的作品里至少有一条提到这个种子名**,才认它属于这一类。
2. **去重**:结果过 `push_ledger`(`section=douyin`),同一批新作品 4 小时一轮不会重复推。

**实跑样本(种子 `狗爹和小桃`)**:

```
10-30 15:50 🐾        狗爹和小桃分开了吗 #狗爹小桃 #狗爹和小桃
10-29 15:23 不会弹琴的小伙 不懂就问 狗爹和小桃 真的分开了吗
```

## 七、自动识别「求1型」大瓜(2026-10-30)

用户口径:「能否**自动监测到这种类型**的大瓜…**特点就是评论区都在发求 和 1**」。

**判据(写死,可调)**:对每条扫过的视频,

```
(整条是 1 的评论数 + 带"求/谁有/在哪看…"语气的评论数) / 已拉评论数 ≥ DEMAND_REQUEST_DENSITY(默认 0.2)
且 (1 数 + 求数) ≥ 3、评论总数 ≥ 5
```

命中 ⇒ 判为「求1型」,单独推一张 **🔥 求1型大瓜 · 抖音** 卡:

```
名字 — 求 N · 扣1 M / 共 T 条 · 作者 X [标题](原视频)
```

- **名字**:先取书名号;没有就取**最长且不在通用词表**的标签(实跑里 `#覆面系`/`#高壮男`
  这类描述词全部挡掉);都取不到就写「(标题里没名字)」—— **仍然推**,因为用户要的是"这类视频"本身;
- **不需要你给视频**:候选池 = 参考作品名搜到的 + 库里最近的推广线索,每轮自动扫;
- **去重**:过 `push_ledger`,4 小时一轮不会重推同一条。

**当前实测**(2026-10-30 17:30,6 条素材):名字 2 个、`求2(无名)`、**求1型 0** ——
现有素材的评论区里还没有"满屏 1"的视频。判据本身有测试守着(密度够就识别、不够不推),
缺的仍是**能命中这类视频的素材源**。

## 八、边界- **只存名字,不落网盘**:本模块从不调用转存/建链;
- 名字来自**公开评论**,卡片上给出原视频链接便于回溯;
- 不做"按名字去找资源"的动作 —— 那是另一条链,得单独评估合规与风险。
