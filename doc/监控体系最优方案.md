## 三、分阶段行动

### P1 本周（零成本，堵最大单点）

1. **✅ 异地备份（R1，2026-09-28 已落地，git 版）**：
   - `scripts/win/offsite_backup.py`：每日把最新快照提交并推送到 GitHub 私有仓库
     `66666666218/redu-backup`（复用本机已有 GitHub 推送密钥，零新增凭证）；
   - 计划任务 `RedianMonitor_Backup` 每小时调起、脚本每日节流；首推实测 13.8MB 成功；
   - 比 scp-to-VPS 少一套 SSH 密钥管理，且 GitHub 自带全部历史版本。
2. **日历提醒**：10-26 前后（wr_rt 满 30 天前）提醒重扫一次微信读书；之后每 28 天循环。
3. **观察期**：连续 3 天看 14:00 轮的运行记录，判读口径见 §五。

### P2 本月（低成本增强，按需）

1. 远程镜像重建拉取最新代码（含续期修复——万一以后要把公众号临时搬回远程当热备）；
2. `redu.tian1she.xyz` 反向代理指回本机（Tailscale + nginx）——出门也能看公众号面板；不做也行，双面板分工已可用；
3. 闲鱼回家试验：更新**本机**闲鱼 Cookie → 本机启用闲鱼、远程停用闲鱼（住宅 IP 过滑块更稳，§10）。

### 已落地（2026-09-28）：热点→网盘选题 Agent v1
监控词热度 ≥50% 时自动对上近 72h 供应商新发资源（有现成资源→「立即跟发」附链；
没资源→ deepseek 生成网盘选题：资源类型/标题模板/关键词），每日 9:10/15:10/21:10
站内推送，同热点 24h 不重复。详见 `app/services/hotspot_agent.py`。

### P3 按需（长期，出现痛点再做）

1. **小主机热备**：出差频繁到嫌 2 分钟烦，或希望出差期间家里也有人盯——家里放一台常开小主机跑监控（Cookie 不再随人走，出差死角彻底消失）。预算几百块；
2. **同日多篇根治**：dajiala 充值只对高产号开 `history_by_ghid` 白名单，或自建 WeRSS（需要公众号后台身份，没有就关闭此路）。

## 四、日常判读表（每天只看这三个信号）

| 看到 | 含义 | 动作 |
|---|---|---|
| 运行记录 `shelf(signals=142 skip=50+ ...)` 且无 `quota_skipped` | 一切正常 | 无 |
| `quota_skipped` 连续 2 轮 > 0 | 密度超预算 | `WEREAD_SHELF_GATE_EVERY` 4→6 |
| 告警「-2012」或「续期失败」连续出现 | 接口又变 / rt 到期 / 换了网络 | 按 §9/§12b 处理（重扫或换新） |

## 五、成本账

- 免费项：微信读书（书架门后约 200 请求/天，额度内）、VPS（已有）、Tailscale（免费档）、快照备份（VPS 磁盘几 MB/天 × 14 份）；
- 付费项：dajiala 采样 ¥0.06/篇（每轮上限 10 篇、仅新文）、约 ¥2.4/天 封顶，实际通常远低；
- 一次性（可选）：小主机几百块（P3）。

## 六、明确不做的事

1. 不把公众号监控搬回 VPS（Cookie IP 绑定，到货即死——9-28 实锤）；
2. 不追「自动过滑块/打码」（对抗成本高、封真号，得不偿失）；
3. 不加密度（4 定点是踩过三次坑换出来的，加密度只会重蹈 9-27 覆辙）；
4. 不为此买新服务器/新数据库（家里本机 + 现有 VPS 足够）。
