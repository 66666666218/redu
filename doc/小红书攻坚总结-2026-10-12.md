## 一、根因

### 1.1 本次复核:仍然是游客档,**未恢复**

按要求重跑了档案扫描:

```
tools/MediaCrawler/.venv/Scripts/python.exe tools/xhs_profiles_scan.py
```

实测输出(2026-10-12 09:0x):

```
共 3 个档案;判据:`web_session` 前缀 04…=真登录态,03…=游客档

⚠️ xhs_1        cookie 14 项  web_session=030037ad8cf2 游客档    id_token=有

```

**没有出现 `04` 前缀**,所以结论不改写为「已恢复」——**链路仍处暂停状态**。

### 1.2 真因:不是签名、不是账号被限,是**身份本身就是游客**

为了把"凭据"这一层单独量出来,又跑了一次分层体检:

```
tools/MediaCrawler/.venv/Scripts/python.exe tools/xhs_session_doctor.py xhs_2
```

实测输出:

```
② cookie 15 项
   必备 ('a1', 'web_session', 'webId'):✅ 齐
   加分项有:['id_token', 'gid', 'websectiga', 'sec_poison_id', 'xsecappid', 'acw_tc']
   web_session = 030037adf565aa… 前缀 03(游客/未知)

③ localStorage 里的 ssk
   ✅ webSsk 有,长度 61

④ 页面内 `user/me`
   HTTP 406: {"code":-1,"success":false}

⑤ 页面内搜索「网盘资源」
   HTTP 200: {"code":-104,"success":false,"msg":"您当前登录的账号没有权限访问","data":{}}
```

这五行输出把四层嫌疑**逐层排掉**:

| 层 | 判据 | 实测 | 结论 |
|---|---|---|---|
| ① 签名 | HTTP 状态码 | 搜索回 **HTTP 200** | ✅ **签名过了**。签名没被拒(被拒是 461/406) |
| ② 凭据齐全度 | `a1`/`web_session`/`webId` + `ssk` | 必备齐、`ssk` 有(61 字节) | ✅ 形状是完整的一套 |
| ③ 会话 | `web_session` 前缀 | **03 = 游客档** | ❌ **身份不是账号** |
| ④ 账号被限 | 业务 `code` | `-104 没有权限访问` | ⚠️ 是**游客的自然结果**,不是处罚 |

⇒ **`-104` 不是"这个号被风控了",是"我们拿游客身份去要只有账号才能要的东西"。**
过去几天把它读成"账号级限制 / 账号在观察期",方向是错的;那个号**可能确实有限制,但这条 `-104` 不构成它的证据**。

### 1.3 一条必须说清的补充:`.env` 里那枚 `04` 是**孤儿**,不能用

写报告时发现一个容易被误读的事实,必须点掉,否则下一个人会以为"我们有 04 啊":

```
.env:140  XHS_WEB_SESSION=web_session=040069b762c6f65d4e270246f0384b6013447d
```

这枚 `web_session` **确实是 `04` 前缀(真登录态格式)**,但它**不是一枚可用凭据**,三个理由:

1. **它没有配对的 `ssk`**。`ssk` 只存在于浏览器档案的 `localStorage`(本次实测 `xhs_2` 里有,61 字节),而 `.env` 里这一行**只是一枚裸 cookie 字符串**;`data/xhs_session_*.json` **不存在**(已确认无此文件),没有任何地方存着和它同源的 `ssk`。
2. **它已经过期**。`.env` 的 mtime 是 **2026-10-11 18:08**,这枚值是那时留下的;而 `xhs_xys.py` 已经证明:**已登录请求缺 `ssk` ⇒ 服务端回 `-100 登录已过期`**。
3. **`.env` 自己的注释就记着它判未登录**(第 144 行):

   > ⏸ xhs_2 的 cookie 注进去了但站点仍判未登录(搜索页显示「登录后查看搜索结果」)

所以精确的根因表述是:

> **两半边从来没合到一起过** —— 档案里有 `ssk` 但身份是 `03` 游客;`.env` 里有 `04` 身份但没有 `ssk`。
> 我们从来没有过一枚「**身份为真 + cookie 与 ssk 同源成对**」的凭据。

这正是 10-11 19:40 那条 CHANGELOG 说的"代码侧已完备,**只差一枚同源的 `(cookie, ssk)`**"——凌晨这一轮把代码侧做完了,**这一半仍然是空的**。

### 1.4 一条工具自身的局限(诚实记录,免得下次误读)

体检工具 ④ 的 `user/me` 回 **HTTP 406 / code -1**,它**不能用来判登录**:
`xhs_session_doctor.py` 的 `page_fetch()` 是在页面里用裸 `fetch` 发的,**没有 `x-s` 签名头**,而 `user/me` 是签名接口 ⇒ 必然 406。
所以"登录态:未能判定"是**工具方法的局限**,不是链路的新问题;**真正可信的判据是 ② 的 `03` 前缀 + ⑤ 的 `-104`**,两者一致指向"游客身份"。

### 1.5 旁证:扫码已经扫得过头了

`data/` 下躺着 **17 张 `xhs_qr_*.png`**。按链路文档 §7 的纪律——**每次扫码都是一次风控输入**——这条纯协议扫码路**已经给不出新信息了**,不要再扫。

## 二、已交付的改动(2026-10-12 凌晨)

按文件列表与作用整理。时间戳均为 2026-10-12 01:09–01:21。

### 2.1 签名:从"在 Python 里复刻算法"改成"让站点自己签"

| 文件 | 作用 |
|---|---|
| `app/services/xhs_sign_oracle.py` | **签名 oracle**。开一个**匿名** headless 页面,直接调站点自己打包进页面的 `window._webmsxyw` 算签名,再截获页面自发请求里的真实 `x-s-common`。 |

它消掉的是一整类维护负担:

| 以前要维护 | 现在 |
|---|---|
| `SIGN_TEMPLATE` 的 `x0` 版本号(4.3.5 → 4.4.3,改版就得追) | **不用了**(页面自带当前版本) |
| `SIGN_ENV_FLAGS` 19 位环境标志(库里错 3 位,曾导致 416 字符里 239 个不同) | **不用了** |
| `HEX_KEY` / 字母表 / 各种前缀 | **不用了** |
| 改版后"比对常量"的排查流程 | **不存在了** |

**实测:匿名页面签名 → HTTP 200**(不是 461、不是 406)⇒ **签名这一关通了**,剩下的 `-100/-104` 是凭据问题。

三条纪律(写进了模块 docstring):
1. 浏览器**全程匿名**,绝不注入 `web_session`(链路文档 §7 坑③:带登录 session 的无头页面一导航,服务端会下发删除指令把 session 作废)。
2. **只借 `a1`**,保证签名里的设备标识与请求 cookie 一致。
3. **是增强不是替代**:起不来(没 playwright / 没浏览器 / 页面改版)自动回落 `xhshow`,整条链不会断。

### 2.2 登录:从"反复扫码"改成"浏览器里登录一次"

| 文件 | 作用 |
|---|---|
| `app/services/xhs_browser_login.py` | Service 层:持久化档案里等真登录态,导出 **cookie + `localStorage["webSsk"]` 成套**凭据;**拒绝把 `03` 游客档写库**。 |
| `tools/xhs_browser_login.py` | CLI:弹真实浏览器窗口给人扫码/短信登录,检测到 `web_session` 变 `04…` 后自动归档并关窗。带 `--timeout` / `--headless` / `--user`。 |

落盘三处:`data/xhs_session_<档案>.json`、`.env` 的 `XHS_WEB_SESSION`、以及写库(写库失败不影响文件已落盘)。

为什么是这条路:纯协议扫码(`tools/xhs_qr_login.py`)状态机能走到 `2`(手机都提示「成功登入」),但 `qrcode/status` 稳定回 **471 + 空 `data`**,**凭据下不来**。浏览器这条路把"设备证明/指纹/风控挑战"全交给真实浏览器,与 `social-auto-upload` 等开源项目做法一致。

### 2.3 诊断:把"签名/凭据/会话/账号"四层分开

| 文件 | 作用 |
|---|---|
| `tools/xhs_profiles_scan.py` | 扫所有 `data/xhs_*` 档案,判定 `04` 真档 / `03` 游客档。**只读不导航**(避免带 session 导航那条风险)。 |
| `tools/xhs_session_doctor.py` | **分层体检**:② cookie 齐全度 → ③ `ssk` 有无 → ④ `user/me` 的 `guest` → ⑤ 登录态下取数。前面不过就不必往后。 |
| `tools/xhs_oracle_probe.py` | 签名 oracle 探针:回答"风控是不是签名不像真浏览器招来的"。 |
| `tools/xhs_oracle_matrix.py` | **对照矩阵**:同一时刻/同一账号/同一关键词,只变签名来源(A 页面签名+匿名 / B 页面签名+真 session / C `xhshow` 复刻+真 session)。B 通 C 不通 ⇒ 是签名;B 也不通 ⇒ 真账号级/出口级。 |

这组分层的价值:**以前四层混在一起,任何一层挂了都长成"被风控了"**。

### 2.4 接线

| 位置 | 改动 |
|---|---|
| `config/settings.py:369` | 新增 **`xhs_sign_oracle: bool = True`** 开关(附完整说明:为什么需要它、实测结果、关闭方式)。 |
| `app/services/xhs_protocol_source.py:265-302` | `search()` 接入 oracle:**优先 oracle**,失败由 oracle 内部回落 `xhshow`(调用方不需要 try);有 `ssk` 时走完整 `XYS_`;两种路径都用**同一份紧凑 JSON**(签名用的字节 = 发出去的字节)。 |

当前开关状态:`xhs_sign_oracle = True`(默认开)。

- **常开**:定时任务(盘链发现 `34 */4`、跨盘发现 `45 */6`、盘清理 `04:20` 等)能稳定落库,代价是常驻内存 + 机器不能随便重启。
