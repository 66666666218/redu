# 抖音纯协议:链路拆解与自修指南

> 2026-10-07 建。姊妹篇:`小红书纯协议-链路拆解.md`。
> 那篇讲的是"签名怎么算";**这篇的核心不是签名** —— 抖音搜索的卡点是**登录态**,
> 而且签名**大概率压根不需要**。先把这一个反直觉的结论记住,往下读才顺。

---

## 0. 四句话结论(时间紧只看这里)

1. **抖音搜索必须登录**。匿名请求回 `HTTP 200 + status_code=2483 +「请先登录,再继续搜索吧」`。
2. **`a_bogus` 不但不必需,加了还会把请求打坏** —— 实测:不带它拿到 **14 条 / 812KB**,
   带它拿到 **0 条 / 3.9KB**(同一账号、同一时刻、只改这一个变量)。所以 `use_abogus`
   默认 `False` 是**实测支持的**,别去"补上签名"。
3. 请求头里的 `x-tt-argus: 1` 要带(别人的注释说缺了会被网关 403),
   但**我们实测没有撞到那个 403** —— 连 `uifid` 都没有也过了。
4. **别连发**。连发 4 次(35 秒内)会把账号推进一种**"空成功"**状态
   (`status_code=0` + `data: []`,约 3.9KB)—— 与"真没搜到"**形状完全相同**。
   实测约 **35 分钟**后自己恢复。`_GAP` 因此定在 **8 秒/词**(见 §5 坑 5)。
5. ✅ **这条路整体是通的**:登录 + 不带 `a_bogus` ⇒ 稳定拿到 13~14 条真数据、
   含**真实作者名**。

## 1. 链路长什么样

```
app/services/douyin_protocol_source.py    ← 拼请求、解析响应(我们写的)
        │
        ├─ build_params()   ← 25 个"设备指纹"式参数 + 业务参数
        ├─ build_headers()  ← UA / Cookie / Referer / x-tt-argus
        └─ build_url()      ← 可选 a_bogus(默认**不加**)
        │
        ▼
GET https://www.douyin.com/aweme/v1/web/general/search/single/?<query>
        │
        ▼
{"status_code":0, "data":[{"aweme_info":{...}}], "extra":{"logid":"..."}}
        │
        ▼
_parse() → 与 mediacrawler_source.crawl 同一形状
        │
        ▼
douyin_leads.collect_leads()   ← 「协议优先、浏览器兜底」就在这里(见 §8)
        │
        ▼
口令解析 → 落库 → 推送卡片

app/services/douyin_sign/            ← 签名(a_bogus / X-Bogus),**f2 的逐字移植**
```

**为什么搬 f2 的源码而不是 `pip install`**:见 `app/services/douyin_sign/NOTICE.md`。
一句话 —— f2 是 9MB 的全能下载器,我们只要那 40KB;而且**改版时源码在自己手里才修得动**。

## 2. 签名(`a_bogus` / `X-Bogus`)

| | `a_bogus` | `X-Bogus` |
|---|---|---|
| 用在 | 抖音 web 当前主用 | 老版本,部分接口仍认 |
| 实现 | `app/services/douyin_sign/abogus.py`(914 行) | `app/services/douyin_sign/xbogus.py`(235 行) |
| 依赖 | `gmssl`(纯 Python SM3) | **零第三方** |
| 调用 | `ABogus(fp=…, user_agent=…).generate_abogus(params)[1]` | `XBogus(ua).getXBogus(query)[1]` |

**两个"以为"会踩的坑**:
- **返回值是元组**:`XBogus` 给 **3 个**、`ABogus` 给 **4 个**,签名在 `[1]`。当字符串用会拼出
  `a_bogus=<tuple>`。形状由 `tests/test_douyin_sign.py` 钉住。
- **UA 与 `fp` 都进签名**。签名用的 UA 必须与请求头里的 UA **完全一致**,否则站点那边对不上。
  指纹 `fp` 每次随机生成是**对的**(真浏览器本来就逐机不同),但**测试里必须用定值**,
  否则金标就成了薛定谔的。

**上游更新了怎么办**:
```bash
python scripts/vendor_f2_sign.py --sha <新提交>   # 先看上游更新到哪
python scripts/vendor_f2_sign.py                  # 重新移植
python -m pytest tests/test_douyin_sign.py -q     # 金标/哈希变了 = 要你确认
```
`tests/test_douyin_sign.py::test_算法体未被改动` 是**有意的绊索**:改了算法体必须在这里红一次,
逼改动被看见。另有一条**外部锚点** —— 上游自己公布的硬编码期望值(`DFSzswVY7OiANnTJtmWx-e9WX7jo`),
它是**独立于我们这份拷贝**的,不是我拿自己的输出给自己对账。

## 3. 接口合同

**端点**:`GET https://www.douyin.com/aweme/v1/web/general/search/single/`

**业务参数**(`build_params`):

| 参数 | 值 | 说明 |
|---|---|---|
| `keyword` | 搜索词 | |
| `search_channel` | `aweme_general` | |
| `search_source` | `tab_search` | |
| `offset` | `0, 15, 30…` | 翻页偏移 |
| `count` | `15` | 单页条数 |
| `search_id` | 首屏**空串** | ★ **翻页用上一屏响应里的 `extra.logid`** |
| `from_group_id` | `7378810571505847586` | ⚠️ **会过期的魔数**;失效表现是"200 但 data 空" |
| 其余 | `enable_history` / `query_correct_type` / `is_filter_search` / `need_filter_settings` / `list_type` | 照抄即可 |

**设备指纹参数**(24 个):`device_platform=webapp`、`aid=6383`、`channel=channel_pc_web`、
`version_code/version_name`、`pc_client_type`、`cookie_enabled`、`browser_*`、`engine_*`、
`os_*`、`cpu_core_num`、`device_memory`、`platform=PC`、`screen_*`、`effective_type`、
`round_trip_time`,外加 `webid`(19 位随机数字)+ `msToken`。

> ⚠️ **`version_code` / `browser_version` 是会过期的** —— 它们是"客户端版本号"的模仿。
> 哪天接口开始回空数据,先怀疑这几个值过时了(去网页版 F12 抄一份新的)。

**请求头**(`build_headers`):

| 头 | 值 | 为什么 |
|---|---|---|
| `User-Agent` | 与签名用的**同一个** | 签名把 UA 算进去了 |
| `Cookie` | 登录态 | **没它 → 2483** |
| `Referer` | `https://www.douyin.com/search/<词>?aid=…&type=general` | 需要 URL 编码 |
| `x-tt-argus` | `1` | 网关 ArgusSecurityPlugin;当前不校验取值 |
| `uifid` | cookie 里的 `UIFID` 或 `UIFID_TEMP` | **两个名字都要认** |

## 4. 凭据从哪来(**这是当前的拦路虎**)

搜索**必须登录**。所以要么:
- 从**已登录的浏览器档案**导出 cookie(像小红书那样:`ctx.cookies()` 解密读,**别手抄**),
  写进**加密 cookie 库**(`user_cookies` 表,平台名 `douyin`),或
- 在 `.env` 里配 `DOUYIN_COOKIE`(回落用;⚠️ `.env` 是 gitignore 的,**值绝不能进仓库**)。

**现成的工具**(2026-10-07 加):

```bash
python tools/douyin_export_cookie.py --check    # 只看关键项齐不齐,不写库
python tools/douyin_export_cookie.py            # 导出进加密库(用户 1)
```

默认读 `tools/MediaCrawler/browser_data/cdp_dy_user_data_dir` —— 那是 `douyin_leads`
**每天在用的号**,已经在生产里跑,不是新增的账号风险。
⚠️ 同目录的 `dy_user_data_dir` 是旧模式留下的(10-03 就停更),**别用错**。
⚠️ 工具**只读、不导航任何页面**,凭据**只写加密库、不打印不落盘**。

⚠️ **必须包含的关键项**:`UIFID`(或 `UIFID_TEMP`)、`ttwid`、`odin_tt`、**`sessionid` 系列**。
实测那个档案给 54 项、齐全;若缺 `sessionid`,纯协议会被回 **2483**。

## 5. 实测踩到的坑(2026-10-07,全部真踩过)

### 坑 1:以为"账号限流是签名没处理好" —— **这次的实测不支持这个假设**
匿名对照组(`tools/douyin_probe.py`,4 次请求):

| 组 | HTTP | status_code | 响应 |
|---|---|---|---|
| A **不带** `a_bogus` | 200 | 2483 | `请先登录,再继续搜索吧` |
| B **带** `a_bogus` | 200 | 2483 | **一字不差** |

⇒ 卡点是**登录态**,签名**根本没轮到被校验**。
⚠️ **结论的边界**:这只证明"**未登录时**签名不是瓶颈",**不证明登录后也不需要它**。

### 坑 2:`x-tt-argus` / `uifid` 的 403 **没有出现**
MediaCrawler 的注释写着"缺 uifid → 403 `Blocked by ArgusSecurityPlugin Uifid Not Found`"。
我们匿名(连 `UIFID_TEMP` 都没有)实测**没撞到**,`x-tt-argus: 1` 一传就过。
⇒ 那条注释**当前不成立**(可能只对某些接口或某个时期)。
两个头照旧带着(免费、无害),但**它们不是现在的瓶颈** —— 别照着旧注释去查错方向。

### 坑 3:匿名首页只发 `__ac_nonce`,拿不到 `UIFID_TEMP`
所以"先去首页蹭一个匿名 uifid"这条路**走不通**,必须真登录。

### 坑 4:★ **带上 `a_bogus` 反而把请求打坏**(登录后实测,这是本篇最有价值的一条)
从 MediaCrawler 用的那个号(`cdp_dy_user_data_dir`)导出凭据后重跑对照:

| 组 | 响应 | `data` | 解析出 |
|---|---|---|---|
| A **不带** `a_bogus` | **812,814 字节** | 14 | **13 条作品**(真实作者名) |
| B **带** `a_bogus` | 3,922 字节 | `[]` | 0 条 |

同一账号、同一时刻、同一份 cookie,**只改了这一个变量**。
⇒ **不是"签名没用",是"签错了会被判成可疑请求"** —— 我们本地算的 `a_bogus`
与请求实际发出的参数/UA/指纹配不上,站点就干脆给空。
**所以 `use_abogus` 默认 `False` 是实测支持的**,别去"补上签名"。
(这也解释了 MediaCrawler 那句看着像笔误的**反条件** `if "/v1/web/general/search" not in uri:`
—— 它是有意的。)

### 坑 5:★ **"空成功"长得和"没搜到"一模一样** —— 已判定:是**限流**
坑 4 之后,同一个号在同一分钟内再发请求,开始**一律**回:

```
HTTP 200 | status_code=0 | data=[] | cursor=0 | has_more=0 | 约 3921 字节
```

这正是**最危险的那类响应** —— 它**不报错**。

**判定过程(照"控制变量 + 找免费对照"走的,最后结论和最初两个猜测都不同)**:

| 步骤 | 做法 | 结果 |
|---|---|---|
| ① 排 `__ac_nonce` | 只改这一个变量:库里 53 项 vs 加上匿名 nonce | 两组**都是 0**、响应同 3921 字节 ⇒ **证伪** |
| ② 排"分钟级限流" | 静默 **7 分钟**后发**单次** | 仍 0 ⇒ 比分钟粗 |
| ③ **免费对照** | 等 `douyin_leads` 那班作业(00:10,走 MediaCrawler 浏览器) | **成功:8 个词、16 条线索** ⇒ **账号没事** |
| ④ 决定性一测 | MediaCrawler 刚成功(00:12),**立刻**再发我们的协议请求 | **13 条** ⇒ **就是限流,已恢复** |

⇒ **结论**:既不是"账号被标记",也不是"我们请求构造错了"(同一份代码现在能跑到数据),
而是**连发触发的临时限流**,约 **35 分钟**自愈。

**两条可操作的推论**(已落到代码里):
1. **`_GAP` 从 1.5 秒改成 8 秒**。生产一轮 4 个词按 1.5 秒跑 = **6 秒内打完**,大概率撞同一个坑;
   8 秒是照**能跑通的对照**取的:MediaCrawler 8 个词花 90 秒 ≈ **11 秒/词**,留了余量。
   测试 `test_间隔不许被随手调小` 是**绊索**,调小会让它红。
2. **"空成功"目前仍无法与"真没结果"区分** —— 这是**没解决的**。
   将来若要加信号(如"连续 N 次空 ⇒ 记一条疑似限流"),**别把它做成静默降级**。

### 坑 6:`_cookie(session=None)` 静默不查加密库(已修)
`_cookie()` 只在**传了 session** 时才去读加密库,否则回落到 `.env`。
而 `.env` 里通常没有 `douyin_cookie` ⇒ 返回**空串** ⇒ 请求不带登录态 ⇒ 2483,
**表现只是"搜不到"**。
当天是靠"库里 53 项 vs 函数读到 0 字节"这个对比才发现的。
现在**没传 session 会明确告警**(`test_没传_session_要报警告`)。

### 坑 7:★ `play_count` 是**假 0**(逐字段核对抓到的)
2026-10-08 抓了一份真实响应(14 条)逐字段对,**我依赖的 6 个字段 13/13 命中**、
5 个统计键也 13/13 —— 名字不是照猜的,交叉核对也对得上(作者名/标题/时间/转发数零不符)。

但同一批数据里:

| 指标 | 实测取值 | 判定 |
|---|---|---|
| `digg_count` / `share_count` / `collect_count` / `comment_count` | 61~321,184 / 106~73,472 / 20~264,295 / 7~3,085 | ✅ 真实 |
| **`play_count`** | **13/13 全是 0** | ❌ **假 0** |

抖音**把字段填 0** 而不是不给(与已知事实一致:播放量是**创作者私有数据**)。
直接采就会把"拿不到"读成"没人看" —— 而且它会**喂给 `conversion.estimate` 算曝光**,
影响的不只是展示。现在这些键**取到 0 时按缺失处理**(`_ALWAYS_ZERO_KEYS`)。

⚠️ **这条也是"条数对不代表字段对"的活例子**:13 条解析得好好的、字段名全中,
里面却藏着一个系统性假值。**只数条数的核对是抓不到它的。**

## 6. 出问题时的排查顺序(照这个走,别乱试)

```
搜索没结果
  ├─ 日志里有 `status_code=2483`?  → **凭据过期/缺失**。重新导出 cookie。与签名无关。
  ├─ `kind=argus`(403 Argus)?    → 缺 x-tt-argus / uifid。检查 build_headers。
  ├─ `kind=restricted`(没有 data 键)? → 风控。**别反复重试**(每试一次都是一次风控输入)。
  ├─ HTTP 200、`data: []`        → 真没搜到。**换个词**再试一次(泛词搜不到是常态)。
  ├─ URL 里参数看着对但全空      → 怀疑 `from_group_id` 这个魔数过期。
  └─ 签名报错                    → 跑 tests/test_douyin_sign.py,再照 §2 重新移植。
```

**别做的事**:改了签名去试、反复重试、换 UA 去试 —— 上面每一条都先有更可能的解释。

## 7. 我们自己那层(不依赖第三方的部分)

- **翻页契约**:首屏 `search_id=""`,之后用上一屏的 `extra.logid`。
  ⚠️ **与小红书恰好相反**(小红书是多页共用一个 `search_id` 才不重复)。搞反会**静默重复**。
- **链接形状**:统一用 `https://www.douyin.com/video/<aweme_id>`(不是接口给的 `share_url`)——
  因为 `douyin_leads._aweme_id` 的正则认 `/(video|note)/<id>`,换域名就断,而去重键断了**会丢线索**。
- **真实作者名**:协议这条路能拿到 `author.nickname` 的**真名**;
  MediaCrawler 教学版是脱敏的(`某***`)。推送卡片的"作者列"因此**终于能显示真名**。
- **指标口径**:拿不到的指标**不填 0**(见 `test_拿不到的指标不填_0`)——
  0 会被读成"没人看",而"平台没给"与"确实是 0"是两回事。

## 8. 现状与待办

### ✅ 已接进生产(2026-10-08)
`douyin_leads` 现在是「**纯协议优先、浏览器兜底**」:
`collect_leads()` 先走协议,只在**协议抛错**或**协议一条都没搜到**时才回落 MediaCrawler。

**回落为什么敢包含"全空"那一档**(这点想清楚再改):
今天(改之前)**每一次都开浏览器**;现在最坏也只是回落回浏览器 ⇒ **不会比今天更贵**,
通常便宜得多(协议约 1 秒/词 vs 浏览器几分钟)。

**开关**:`douyin_leads_use_protocol`(默认 `True`)。要回滚就关它,不用改代码。

**★ 排障第一眼:运行记录里的来源标签。** `run_records.detail` 现在长这样:

```
douyin[协议] 类目问卷 词4(其中外部1) 线索13 ...
douyin[浏览器兜底] 类目问卷 词4(其中外部1) 线索8 ...
```

看 `0 条` 时**必须先看这个标签**:`[浏览器兜底]` 意味着协议那边出事了(日志里有 kind),
`[协议]` + 0 条才比较像"真没人在推"。不标来源的话这两件事长得一模一样。

### 待办
1. **给"空成功"加信号**(§5 坑 5):连续空 + 距离上次太近 ⇒ 记"疑似限流"。
   ⚠️ 别做成静默降级;也不要因为"分不出来"就假装它不存在。
2. **想要多页**:翻页要用上一屏的 `extra.logid` 当 `search_id`(§3)。第一版只跑单页。
3. **滚动复核**:协议接上后,盯一周 `[浏览器兜底]` 出现的频率 ——
   频繁回落说明协议那边有系统性问题(凭据过期?限流?),别让它变成常态噪音。

### 已经拿到的东西(别再重做)
- ✅ **签名**:`app/services/douyin_sign/`(f2 移植),离线自证齐全(外部锚点 + 哈希绊索)。
- ✅ **合同**:参数/头/翻页方式已复刻并**离线测过构造**(38 个参数、头齐全)。
- ✅ **★ 这条路是通的**:登录 + **不带 `a_bogus`** ⇒ 稳定 13~14 条真数据、含真实作者名。
- ✅ **`a_bogus` 是负面的**:带上它请求被打坏(§5 坑 4)⇒ `use_abogus` 默认 `False`。
- ✅ **字段已逐字段核对**:6 个字段 + 5 个统计键全中,并抓出 `play_count` 假 0(§5 坑 7)。
- ✅ **节奏**:`_GAP = 8 秒/词`,并有一条绊索测试守着(§5 坑 5)。
- ✅ **凭据导出**:`tools/douyin_export_cookie.py`(只读、不导航、值不落盘)。
- ✅ **探针**:`tools/douyin_probe.py`(对照实验;**它一次发 4 次请求,别连着跑**)。
