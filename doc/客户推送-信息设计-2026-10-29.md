# 客户推送:信息设计(2026-10-29)

> 用户口径:「客户角度主要是**看推文来进行网盘拉新**,怎么更方便更快速地**找到有用信息**」。

## 一、客户真正要什么(按优先级)

| 优先级 | 信息 | 为什么 |
|---|---|---|
| 1 | **这条能不能直接取用** | 不能取用 = 对他的拉新没有价值,只是"看到别人在推" |
| 2 | **在哪个盘** | 夸克/迅雷/百度的转存体验与受众不同 |
| 3 | **资源名** | 他要拿去写自己的标题/文案 |
| 4 | 热度/对标数据 | 判断值不值得跟 |
| 5 | 何时发的 | 判断还来不来得及 |

## 二、这一版改了四处

1. **抖音线索卡:卡头先给答案**
   `可直取 N 条(夸克 x / 迅雷 y)· 需自己找 M 条` —— 客户不用逐行扫「资源」列去找哪条有链。
2. **抖音线索卡:可直取的排前面**
   组内按「有链优先 → 发布时间新→旧」排,同赛道里先给能用的。
3. **跨平台热度卡 / 知乎盘链卡:同一句摘要**
   热度卡:`可直取 N 条 · 其余 M 条只有对标作品`(这些板块本来就有 82%~100% 带盘);
   知乎卡:`可直取 N 条(盘名分布)`。
4. **修了台账丢链(数据问题,比排版严重)**
   线索的链**嵌套**在 `kouling.our_url` / `library.link` 里,而台账只认顶层 `pan_url`
   ⇒ 实测 **1,495 行 `douyin_peer` 的 pan_url 全空**,而近 3 天线索里 **90/132(68%) 其实有链**。
   后果:板块**日结/周结**的「资源」列整列是「—」,客户以为没链、也点不动。
   现在推卡时把**解析后的链**一起写进台账 ⇒ 日结自动变成可点。

## 三、还没做(下一步候选)

- **一键复制口令**:飞书卡片里口令只能显示、不能一键复制;可以改成"口令 + 短链"并列。
- **按"能用"分批**:第一张卡只放可直取的,第二张放"只能对标"的 —— 客户先拿货、再看行情。
- **日结也按赛道分组**(现在只有实时卡分组)。

## 四、分批 + 日结分组(2026-10-30,按优先级落地)

1. **抖音线索拆两张卡**:
   - 第一张 **「可直取 N 条」** —— 只放有链的,标题点开即网盘;
   - 第二张 **「只能对标 M 条(暂无盘链)」** —— 明说"先看别人怎么推,等转存成功再取用";
   - 两张各自入推送台账(只记真的发出去的那张)。
   ⇒ 客户不用在长卡里自己挑哪条能用。
2. **日结/周结按赛道分组**:卡头写 `赛道:漫剧 12 · 短剧 3 · 资料 2`,
   行按组排列、每组 `▍赛道` 小标题,**序号在分组后仍连续**。
3. **没做「一键复制口令」**:飞书自定义机器人卡片不支持复制按钮;目前口令是纯文本
   (`🔑xxxx`),手机端可长按选中。要做到真一键,得换应用机器人/交互卡片,成本高、先不动。

## 五、带链但没转存也可以推(2026-10-30)

用户口径:「**如果是带链只是没有转存也是可以推送的**」。

- 「可用网盘链」现在包含 **作者原始分享链** `kouling.share_url` —— 我们没搬成/超额度/盘满时它照样在;
- 卡片行为:标题点开 = 作者那条盘链,「资源」列写盘名(如 迅雷),摘要计入「可直取」;
- **群口令仍不算**(能进群,但卡片上没有可直接点的链接);
- 判据只在"有没有链接",**不要求我们已经转存**。
