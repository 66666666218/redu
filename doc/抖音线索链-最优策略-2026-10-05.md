# 抖音线索链:最优策略(2026-10-05)

> **这条链的唯一目标**:发现**新的群**与**新的我方链**。
> 不是"看大家在聊什么",不是"线索数好看"。下面每一条都拿**库里的真实数据**说话。

---

## 一、先立对指标 —— 现在的判据把"零产出"也算了进去

现在的运行记录写 `线索2`,而"线索"里混着 `kind=none`(**搜到抖音视频,但标题里没有《口令》**)
—— 那是**零产出**,却和真产出挤在同一个数里。

**立正确判据**:

```
有效率 = (新群 + 新链) / 线索
```

数据现成:`douyin_leads.keyword` **43/43 全填**,一条 `JOIN` 就能算出每个词的有效率。
**但这个数据从来没被用来选过词** —— 这是本策略最大的抓手。

---

## 二、实测:两类词源的有效率差 86 个百分点

| 词源 | 线索 | 有产出 | **有效率** |
|---|---|---|---|
| **热榜种子**(剧名/明星/事件) | 5 | **0** | **0%** |
| **资源名** | 29 | 25 | **86%** |

**资源名一侧的样本**:

| 词 | 线索 | 新群 | 新链 | 有效率 |
|---|---|---|---|---|
| 霸王茶姬杯贴自定义入口链接直达 | 7 | 0 | **7** | **100%** |
| 手机警报器 | 3 | 3 | 0 | **100%** |
| diplay | 2 | 2 | 0 | **100%** |
| 高性价比人生指南共338页pdf | 9 | 0 | **7** | 78% |
| 白泽的梦 | 8 | **6** | 0 | 75% |
| 兰香如故(热榜种子) | 5 | 0 | 0 | **0%** |
| 武林外传十级考试 | 2 | 0 | 0 | **0%** |
| 余红旧事 | 2 | 0 | 0 | **0%** |

**根因**:热榜种子是**剧名/明星/事件** —— 抖音上这些话题下的视频在**讨论内容**;
而资源名(高性价比人生指南 / 霸王茶姬杯贴 / 手机警报器)—— 推广号**就是拿这些当标题**。

**而热榜种子每轮占 3/7 个名额(43%)** ⇒ **约四成搜索名额花在 0% 有效率的词上。**

⚠️ 样本只有 5 条,**不代表已定论**;但方向上讲得通,且**代价明确**(见下面的阶段一)。
先降额、单独计量,样本够了再决定要不要彻底去掉。

## 三、策略骨架:证据位 / 探索位 / 外部位

**名额分配**(以每轮 7 个词为例):

| 档位 | 词从哪来 | 名额 | 依据 |
|---|---|---|---|
| **证据位** | ① 高产出词(历史有效率高的)② 共振词(≥2 号同发)③ 群里的资源名 | ~5 | **有效率 86%**,这是主料 |
| **探索位** | 本类目资源名 / 本类目话题词 | ~1-2 | 保**广度**,不困在同一方向 |
| **外部位** | 热榜种子 | **1**(现在 3) | 有效率 0%,**降为兜底**:证据词不够时才补 |

⚠️ **顺序不能反**:证据位 > 探索位 > 外部位。今天之前是"类目轮换压过证据"
(实测把 4 个共振验证过的真资源名丢光、换成泛词「软件」),**已经在 `pick` 里限量修正**;
这一节是把同一原则推到**词源配额**层面。

## 四、五个具体机制

### 1. 词级评分(把已有的数据用起来)

```
score(词) = 历史有效率,样本不足时回落到中性值
```
- 有理有据的排序,**替代**现在的"新鲜度优先"(`order="fresh"`)
  —— 那条规则是 10-04 定的,当时**还没有产出数据**;现在有了,该让它说话。
- ⚠️ 小样本要收缩(如 5 次里 1 次成功 ≠ 20%),否则一个走运的词会霸榜。

### 2. 高产出词"深挖变体"

`霸王茶姬杯贴自定义入口链接直达` 100%、`高性价比人生指南共338页pdf` 78%
—— 推广号做这类资源**往往一次做一批**,换个数字/后缀就是另一个视频。

⇒ 对高产出词**生成变体**(换数字、去掉"自定义入口链接直达"这类后缀、加"2026/最新")继续搜。
**这是"探索"的正确方向:沿着已验证的方向探,而不是沿着类目探。**

### 3. 零产出词冷却(不是删)

`武林外传十级考试` 0/2、`余红旧事` 0/2 —— 连续 N 轮零产出的词 排到队尾,但**保留**
(热度会变、资源会重新上架)。现有 `_words_already_resolved_to_group` 已经是这个思路,
只是判据是"解出过群没有",**比"有效率"粗**。

### 4. 产出必须落到"新"

这条链要的是**新**群/新资源 —— 已经进过的群、已经转过的链**不算产出**。
- 群:`newly_joined` 已经区分了 ✅
- 链:`our_url` 是**本次新产生**的才算(不是 `already` 捡回来的)⚠️ 见下一节

### 5. 让"哪档词源在起作用"看得见

运行记录里按档位分开报:`证据位5(有效率83%) 探索位1 外部位1(有效率0%)`。
**恒为 0 的那一档要能一眼看出来** —— 与 `chain_health` 那条"恒 0 的档位是'接了但没生效'的信号"同源。

## 五、执行顺序(按"影响 ÷ 成本")

| 阶段 | 做什么 | 为什么先做它 |
|---|---|---|
| **P0** | 热榜种子 **3 → 1** 个名额 | 一行配置,直接回收 2/7 名额(≈29% 的搜索预算);0% 有效率的证据已经够支撑"先降额" |
| **P0** | 运行记录**分开报**各档位 + 有效率 | 不做这个,后面每一步都看不出有没有用 |
| **P1** | 词级评分(用 `douyin_leads.keyword` 的产出) | 把手上的 data 用起来;**排序依据从"新鲜"换成"有效"** |
| **P1** | 零产出词降权(判据从"解出过群没"升级为"有效率") | 现在那条太粗 |
| **P2** | 高产出词生成变体继续搜 | 是"探索"的正确方向,但**要有 P1 的评分托底**才知道该深挖谁 |
| **P2** | 链的产出判据收紧成"本次新产生" | 现在会把 `already` 捡回来的也算进去 |

**不做/慎做**:去掉类目轮换。它保的是**广度**,证据位已经限量放行(2026-10-05 修),
两者不冲突;真去掉会困在少数几个方向里。

## 六、怎么知道策略对不对(验证方式)

1. **每轮记 `有效率`**,看它是否随策略调整上升(基线:全历史 **25/43 ≈ 58%**;
   其中资源名 **86%**、热榜 **0%**)。
2. **新群数**是最硬的判据 —— 它是"往外扩"的唯一证据(`_kouling_summary` 里那个 `新群N`)。
   ⚠️ 用户 10-04 的原话:"而不是一直用着一个口令进群,我们是需要创新的"。
3. **两个方向都要看**:只涨有效率的策略可能只是"把容易的又搜了一遍"。
   ⇒ 每轮同时看 **新群数** 与 **有效率**,一个掉了就要查。

## 七、赛道平衡(2026-10-29)—— "每个板块都能监测到"

**用户口径**:

> 「抖音同行监控我感觉短剧比重太大了,因为**也有做小游戏的**,但每轮推送基本都是短剧相关的,
>  是否能找一个平衡点**每个板块都能监测到**,而不是每次都是一个板块」

### 7.1 实测:轮换在跑,但产出几乎全是影视

近 3 天(`douyin_leads`,共 150 条)按 `category_topics.classify` 归类:

| 影视 | 其他(判不出) | 资料 | 软件 | 大瓜 | 问卷 | **小游戏** |
|---|---|---|---|---|---|---|
| 69 | 64 | 10 | 5 | 5 | 0 | **0** |

运行记录里类目**确实在轮换**(`类目影视/资料/大瓜/软件/问卷` 每 4 小时一换),
但**实际搜出去的词**仍是清一色短剧资源名 + 通用口令词,比如 10-29 00:16 那轮
`类目大瓜`,词是 `《顶级差距》1 / 咐置 / 夸克口令 / 直n室友 / 训犬大师车内🚗`。

四个原因,一条一条修:

| # | 根因 | 修法 |
|---|---|---|
| 1 | 类目表里**根本没有「小游戏」** ⇒ 库里 38 个游戏资源全判成「未分类」,轮换永远轮不到 | `DEFAULT_CATEGORIES` 加 `小游戏`(词表刻意不含「仙侠/武侠/传奇」:短剧标题里到处都是,放进来会把短剧抢成小游戏) |
| 2 | `pick` 的名额**先到先得** —— 别的类目资源名 + 未分类词一占满,本类目话题词一个都进不去 | `pick(min_mine=1)`:本类目**没有资源名时保底 1 个**它自己的话题词 |
| 3 | 三个通用口令词(`夸克口令/咐置/网盘口令`)**每轮无条件全加**(8 个词里占 3 个),而它们不携带赛道信息 —— 实测 `咐置` 一个词就 204 条线索,几乎全是短剧 | `douyin_leads_quark_slots=1`,且**起点跟着类目游标轮换**(三个词轮流用) |
| 4 | 推送卡片是一串按时间排的行,别的赛道**看得见但被淹掉** | 卡片**按赛道分组**(稀缺赛道排前、`其他` 垫底)+ 卡头写「本轮赛道:小游戏 1 · 影视 8」;运行记录也带 `赛道…` |

### 7.2 边界(别把这一节读成"泛词比资源名好")

本文第三节的实测仍然成立:**资源名 86% / 泛话题词 0%**。所以保底**只给 1 个名额**,
不砍资源名、不动证据位。要更用力地朝冷门赛道倾斜,把
`DOUYIN_LEADS_CATEGORY_MIN_WORDS` 调大(2 = 一半名额给本类目话题词)。

另:`classify` 对**只有剧名、没有类目词**的短剧标题仍然判不出(近 3 天 64/150 落进「其他」)。
这次只补了 `番外`/`大结局` 两个结构词(未知占 42/60 → 37/60),没有为了凑数去加
「集」「仙侠」这类会误伤的词 —— **推错赛道比不推更坏**。

### 7.3 怎么验证有没有效果

1. 运行记录里新增 `赛道小游戏1/影视3/其他2` 一段 —— **恒为「影视N」= 没覆盖到**。
2. 卡片上的「本轮赛道」一行 + 分组小标题。
3. 一个轮换周期(6 个类目 × 4 小时 = 24 小时)内,`小游戏` 至少应出现 **1 轮**;
   连续 3 天一次都没有 ⇒ 轮换游标或类目表被改坏了,先查 `lead_word_category`。

## 八、对标号监控(2026-10-29)—— 小游戏这类"没有口令"的赛道怎么覆盖

**用户口径**:

> 「你也可以找几个**对标账号**来看,其实有很多**小游戏的对标账号**的,**他们发了你就能看到**,
>  或者你还有更好的办法」

### 8.1 为什么关键词那条路覆盖不了小游戏(实测,不是推理)

2026-10-29 用生产登录态实测搜 `小游戏 / 小游戏推广 / 抖音小游戏` 三个词:

| 结果 | 数 |
|---|---|
| 返回作品 | **47** |
| 其中判成「小游戏」 | **46**(`category_topics` 分类直接可用) |
| 其中带《口令》/夸克标记 | **0** |

⇒ 两个硬结论:
1. **分类没问题**(46/47);
2. 但这些作品用的是 `#话题`,**没有网盘口令** ⇒ `collect_leads` 会**全部丢掉**,
   卡片上一条也不会出现。而且搜索返回的是"当前最热"的那批(实测大量 1 周 / 3 个月 / 11 个月前)
   —— 每轮都一样,**没有"新"的语义**。

### 8.2 做法:按 **sec_uid** 看主页新作品

- 账号存 `cross_platform_accounts`(`platform="douyin"`,`uid` = sec_uid);
- 每轮打开 `https://www.douyin.com/user/<sec_uid>`,读首屏作品(视频 id + 标题 + 点赞数);
- **只推没见过的 `aweme_id`**;首次扫描**只建基线、不推**(新号主页 20+ 条旧作品,全推=上线即刷屏);
- 卡片按**赛道**分组(与线索卡同一口径 `category_topics.niche_of`),落推送台账。

实测(同一批号,2026-10-29):

| 账号 | 主页可见 | 其中小游戏 |
|---|---|---|
| 抖音小游戏 | 26 | 18 |
| 糖糖（小游戏推广） | 25 | 16 |
| 阿德·游戏解说 | 25 | 18 |
| 小明游戏宅 | 26 | 18 |

### 8.3 怎么加号 / 停用

```bash
python scripts/douyin_peer_add.py --name 抖音小游戏      # 按名字搜索 → 精确同名才收
python scripts/douyin_peer_add.py --uid MS4wLjABAAAA... --label 显示名
python scripts/douyin_peer_add.py --list                 # 看现在监控了哪些
python scripts/douyin_peer_add.py --remove <sec_uid>     # 停用(不是删)
```

⚠️ **同名号很多**(实测「小游戏推广」有 3 个不同 sec_uid,主页内容完全不同):
脚本**只认完全同名**;有歧义就列候选并停下,**绝不替你猜**。

### 8.4 边界

- **一个号失败不拖垮整轮**;但**全部失败必须抛**(验证码/未登录不能记成"这些号今天没发东西")。
- 慢活(开页面)全部做完**再写库** —— 写点不在浏览器会话里持有 SQLite 写锁。
- 第一轮运行记录里会出现 `**建基线:…**`:那是设计如此,**不是坏**;之后出现新作品才会推。

### 8.5 上线后补的三处(2026-10-29,同一天)

| 问题 | 改法 | 为什么 |
|---|---|---|
| 新作业**没进体检** —— 本仓栽过「有运行记录、没有任何报告会读到它」 | `chain_health.CHAINS` 加「抖音·对标号」 | 否则它挂了只在 `runs` 里,没人看 |
| 体检指标该取什么 | 取 **`作品`**(本轮读到几条主页作品),**不取 `新`** | 号不是每轮都发东西,`新0` 是常态;拿它判黄会把「安静」报成「坏了」。`作品0` 才是真坏了 |
| 3 个号里 1 个读不到 | 运行记录写 `失败:名字` + 卡片账号名可点主页 | 逐号失败不许被总数掩盖;追一个新号不该再去抖音里搜名字(同名号一堆) |

另:`douyin_peer_max_works` **6 → 12** —— 主页首屏实测就有 25~26 条,**多读 DOM 不开页面**;
取 6 条时高频号一轮发 >6 条会漏(旧作品被挤到第 7 位之后,永远轮不到),漏掉的永远不会被判成「新」。
