# 贴吧纯协议:链路拆解与自修指南

> 2026-10-08 建。姊妹篇:`小红书纯协议-链路拆解.md`、`抖音纯协议-链路拆解.md`、
> `闲鱼纯协议-链路拆解.md`。
> **这篇的核心是一句话**:盘链**不在搜索返回里** —— 搜索给的是**截断的摘要**,
> 必须再取一次**首楼全文**才抽得出链。

---

## 0. 结论(时间紧只看这里)

1. 用 `aiotieba`(**已经是本项目的依赖**)的 `search_global`,**匿名**即可 ——
   不开浏览器、不要 BDUSS、不要登录档案。
2. ★ **但光调 `search_global` 拿不到盘链**:它的 `content` 是**截断的摘要**,
   实测**一个词 0 条链**。要再用 `get_posts(tid)` 取**首楼全文**。
3. A/B 实测(同一个词「网盘资源」):

| | 纯协议(aiotieba) | 浏览器(MediaCrawler) |
|---|---|---|
| **带盘链** | **19 条** | 16 条 |
| 耗时 | **12 秒** | 60 秒 |

4. 采集路径已改成**协议优先、浏览器兜底**;开关 `TIEBA_PREFER_PROTOCOL`。

⚠️ **还没验的**:翻页未验;连发上限没探;贴吧对**同一个出口**的频次容忍度未知。

## 1. 链路长什么样

```
app/services/tieba_search.py    search(keywords[, with_detail])
        │
        ├─ ① aiotieba.search_global(词, rn≤50)     ← **匿名的**,搜出 tid + 截断摘要
        ├─ ② aiotieba.get_posts(tid)               ← ★ 取**首楼全文**(每个帖子一次请求)
        └─ ③ 从全文抽盘链 → 统一记录形状
        │
        ▼
app/services/pan_discovery.py   _candidates_from_tieba()   ← 主源(实测产出是知乎的 3 倍)
app/services/resource_presence.py  _crawl_platform("tieba")  ← ★ 只数条数,**不要详情**(省 N 次请求)
```

**两个消费者的需求不同,别一刀切**:

| 调用方 | 要什么 | 怎么调 |
|---|---|---|
| `pan_discovery` | **盘链** | `search(keywords)` —— 必须带详情(链只在全文里) |
| `resource_presence` | **"这名字出现了几次"** | `search(names, rn=50, with_detail=False)` —— **省掉全部详情请求** |

## 2. ★ 关键:`contents` 不是 `content`

取首楼要读楼层对象的 **`contents`**(富文本片段列表:`FragText` / `FragLink`),
**不是 `content`** —— 后者恒为 `None`。

⚠️ 我第一版读 `content`,拿到"首楼 **0 字**",差点把结论写成
"匿名取不到全文,所以纯协议不可行"。**差一点又是一次错误的证伪。**

链接片段长这样:

```
FragText(text='…《天道》全集4K百度网盘完整版观看下载链接:\n百度网盘:\n')
FragLink(text='tiebaclient://swan/…?action=preview_fil…',
         title='百度网盘',
         raw_url='tiebaclient://swan/…')      ← 真链在深链的查询串里(编码过)
FragText(text='\n提取码:knm2\n【精品资源极易和谐,请先存后看~失效不补!!】…')
```

⇒ `flatten_contents()` 要把 `text` / `title` / `raw_url` **都**拍进来,
调用方再 `unquote` 一次才能抽出链(见 `tieba_metrics.flatten_contents`)。

## 3. 接口

| 做什么 | 调用 | 说明 |
|---|---|---|
| 全吧搜索 | `search_global(query, pn=1, rn=20)` | `rn` 上限 **50**,>50 服务端退化成 10 条;**只搜主题帖** |
| 吧内搜索 | `search_in_forum(fname_or_fid, query, …)` | 没用上,备查 |
| 取楼层 | `get_posts(tid, with_comments=False)` | **`tid` 必须是 int**(传 str 会报 `'str' object cannot be interpreted as an integer`) |

**字段映射**(`SearchGlobal` → 我们的统一形状):

| aiotieba | 我们 | 备注 |
|---|---|---|
| `tid` | `url = https://tieba.baidu.com/p/{tid}` | 也是去重键 |
| `title` + `content` | `snippet` | 摘要是截断的,**别拿它抽链** |
| `author_name` / `author_show_name` | `name` | |
| `author_id` | `uid` | |
| `create_time` | `publish_at` | ★ 比 MediaCrawler 那条**多**给的 |
| `forum_name` | `forum_name` | 排障时一眼看出这条来自哪个吧 |
| `post_num` | `metrics.comment_count` | **回复数**(aiotieba 字段说明原文),不冒充转发 |
| 首楼 `agree` | `metrics.liked_count` | ★ **取全文那一次顺带回来的**,不额外花请求 |
| — | `share_count = 0` | 贴吧**没有转发数**;给 0 是为兼容老列(`int` 没有 `None`) |

## 4. 踩过的坑

### 坑 1:★ 拿摘要抽链,一条都抽不到
`search_global.content` 实测 **75~85 字**,而且**刚好断在链接前面**:

```
…《天道》全集4K百度网盘完整版资源_百度网盘下载_百度云网盘资源整理好了,链   ← 断了
```

⇒ 直接用它抽链,一个词 **0 条**(A/B 实测);取首楼全文后 **6/6 都有链**。
这也是"**条数多不等于产出多**"的又一例:浏览器那条 89 条 / 16 条链,协议 20 条 / **19 条链**。

### 坑 2:`content` 恒为 `None`,正文在 `contents`
见 §2。差点据此把"可行"判成"不可行"。

### 坑 3:链接是**编码过**的深链
`FragLink.raw_url` 是 `tiebaclient://…?url=https%3A%2F%2Fpan.baidu.com%2Fs%2F…`,
不 `unquote` 抽不出来。

### 坑 4:测试会偷偷发真请求
贴吧改协议优先后,`tests/test_pan_discovery.py` 那 3 条(它们只打了 `crawl` 的桩)
会**真的往贴吧发请求**,而且协议一成功,那些"crawl 抛错"的用例就永远走不到。
⇒ 加了 autouse fixture 把它们钉回浏览器路(`tieba_prefer_protocol=False`)。

## 5. 出问题时的排查顺序

```
贴吧没产出
  ├─ 候选有、盘链 0     → **详情那一步没跑**(看日志「取到 N 条首楼全文」)
  │                       → 若是 `with_detail=False`,那是调用方故意的(presence 那条)
  ├─ 候选 0             → 搜不到;换个词再看(裸词命中差,搜索词要带"网盘/资料"限定)
  ├─ 节点报错           → `TiebaSearchError(kind=dependency)` = 没装 aiotieba
  │                      `kind=api` = 接口变了 → 去看 aiotieba 是否要升级
  └─ 日志有「回落浏览器」 → 协议挂了,**先看 kind 再决定**,别直接怪贴吧
```

**别做的事**:改 `_GAP` 去提速、连发试探 —— 上限没探过,要探**先问用户**。

## 6. 现状与待办

### ✅ 已接进生产(2026-10-08)
- `tieba_search.search()` —— 形状与 `mediacrawler_source.crawl` 一致,上层不用改。
- 两个消费者都接上了(`pan_discovery` 带详情 / `resource_presence` 不带),
  规则只有一处、**需求不同这件事写在 docstring 里**。
- 回落:**协议失败自动回落浏览器并记日志**;`TIEBA_PREFER_PROTOCOL=false` 可整条回滚。
  ⚠️ **不会比之前更差**:2026-10-08 之前**每一次**都开浏览器。
- 顺带把 `_run_async` 提升成 `app/utils/asyncrun.py`,并**修掉一个静默失败**:
  原实现超时后 `return box.get("r")` 会返回 `None`,让调用方把"没跑完"读成"没数据"。
- 测试:`tests/test_tieba_search.py`(13 条)+ 变异测试
  (关掉 `with_detail` / 失败返回空列表,两种改动都会被抓到)。

### 待办
1. **翻页**:只跑了 `pn=1`。
2. **频次容忍度**:匿名接口能连发多少次没探(要探先问用户)。
3. **快手**:现在**唯一**还在 MediaCrawler 里的平台。查下来**没有可用的开源实现**
   (签名 `__NS_sig3` 是混淆 JS;现存 repo 要么 2018 年的、要么 1⭐ 无许可;
   唯一像样的 `KS-Downloader` 是 **GPL-3.0**,代码不能抄)⇒ 要做只能自己逆向,先放着。
