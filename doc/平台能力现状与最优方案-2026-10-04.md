# 平台能力现状与最优方案(2026-10-04)

> 起因:用户问「B站/小红书/知乎/贴吧什么情况能不能优化」「多平台监控 newsnow 怎样现在运行的」
> 「容器没用的就别留了」「能不能把这个能力写进我们项目里,不再依赖别人的容器」。
>
> 本文把**实测判据**和**取舍**钉死,免得下次又靠印象决定去留。

## 一、结论先行

| 问题 | 结论 |
|---|---|
| WeRSS 容器能删吗? | ❌ **不能**。它的 `search_mp` **是活的**,而且是「号名 → `MP_WXS_*`」这条链上**唯一可用的解析器**(实测见 §2) |
| newsnow 容器呢? | ⚠️ 本机这个**已经没用**(Exited 2 天)。但**不是"删掉不影响"** —— 它背后 41 个长尾平台**现在全黑**,是**静默降级**(§4) |
| 能完全不依赖别人的容器吗? | ✅ **能,而且这正是本项目自己的原则(「命门自持」)**。路径明确,但要**分阶段**(§5) |
| 最该先做的 | ① 让 newsnow 的数据**先回来**(配一行地址,零代码)② 给自研 `WempClient` 补 `search_mp`(摆脱 WeRSS) |

## 二、容器去留:判据是实测,不是印象

### 2.1 WeRSS —— `search_mp` 是活的,**必须留**

`_source.py:283-288` 早就写明了关键事实:

> WeRSS 的订阅 id 是 `MP_WXS_<base64解码(fakeid)>`,**与微信读书的 bookId 同一编号**

也就是说,WeRSS 在本项目里**根本不是"文章抓取器"**(它 `articles` 表 0 行),而是
**"号名 → fakeid"的解析器**。2026-10-04 实测(容器起来后逐条对答案):

| 号名 | WeRSS `search_mp` 返回的 fakeid | base64 解码 | 库里已知的 `weread_book_id` |
|---|---|---|---|
| 小猫爱吃米 | `MzkwMjcxNDA5NQ==` | 3902714095 | `MP_WXS_3902714095` ✓ |
| 索子时光 | `MzY4NTQwODU0OA==` | 3685408548 | `MP_WXS_3685408548` ✓ |
| 天一项目拆解 | `MzcwMzMwMzIwNg==` | 3703303206 | `MP_WXS_3703303206` ✓ |
| 凌霄0412 | `MzcwNDM5NzE1MQ==` | 3704397151 | `MP_WXS_3704397151` ✓ |

**四个全部精确对上。** 端到端也通:`_subscribe_by_name("一诺农旅规划")` → `MP_WXS_2392531081`。

⚠️ **本文档记录一次误判**:当天我因为"WeRSS 抓不到文章"就删了容器 + 镜像 ——
**没测它另一个能力**。删完才发现 `search_mp` 是活的。容器已用快照恢复
(`D:\werss\we-mp-rss-image-20260930.tar`,`docker load` + `scripts/win/setup_werss.bat` 一条命令)。
**教训:「它这方面没用」≠「它没用」—— 删之前要把它的每个能力都过一遍。**

### 2.2 `listenable=0` 不是故障

运行记录显示 `wechat_candidate_import` 在 `2026-10-01 14:13~14:20` 是
`listenable=18/11/15/11/3`(共 58 = 候选表里 `imported` 的总数),之后每天 08:30 变成 `0`。

**实测排除了"链断了"**:直接调 `_subscribe_by_name` 三个候选名**全部成功**。
真相是**排到队头的那几个候选名,规范化后对不上**:

| 候选名 | 搜索结果 | 精确同名 |
|---|---|---|
| 谦虚的L小宏hong | 0 个 | 0 |
| 文科园林 | 8 个 | 0(都是形近号) |
| 深圳老有才了 | 10 个 | 0 |
| 一诺农旅规划 | 5 个 | **1** ✓ |

这正是 `_subscribe_by_name` 的既定设计:「**拿不准一律空串,不猜**;形近号一律不认」。
⇒ 它**不是静默失败,是保守策略正常生效**。

### 2.3 newsnow —— 本机这个确实没用了

`Exited (0)` 两天,而且本机 `hot_source` 作业 `role=hotspot` 而本机 `SCHEDULER_ROLE=wechat`
⇒ **本机根本不注册这个作业**,容器即使拉起来也没人调它。

## 三、四个平台:角色矩阵与实测

⚠️ 关键前提:这 4 个平台**各自扮演多个角色**,不同角色走**完全不同的技术路线**,
混为一谈就会得出错误结论。

| 平台 | 角色 | 技术路线 | 本机跑? | 实测 |
|---|---|---|---|---|
| **B站** | 热榜 | **自研直连**官方 API | ❌(hotspot) | 命中 100%(200 条) |
| | 账号发现 | **自研** wbi 搜用户(匿名可算) | ✅ 周一/四 09:00 | **一次拿 20 个号,59 个全是网盘号**(最强) |
| | 名字型热度 | **自研** wbi 搜视频 | ✅ 每天 09:00 | 在跑 |
| | 盘链发现 | — | — | 未参与 |
| | 口令线索 | — | — | ❌ **实测排除**(标题带网盘词 0) |
| **知乎** | 热榜 | ⚠️ **newsnow 容器** | ❌(hotspot) | **全黑**(§4) |
| | 账号发现 + **盘链直链** | **自研**搜内容(需 Cookie) | ✅ 每天 11:30 | 命中 **17.8%**;频控 403(连打 20+ 次) |
| | 名字型 | — | — | 未参与 |
| **贴吧** | **盘链发现(主源)** | MediaCrawler | ✅ 每天 11:30 | **命中 56%**(知乎的 3 倍);死链率高(17 条里 15 条失效) |
| | 热榜 | ⚠️ **newsnow 容器** | ❌(hotspot) | **全黑** |

**读法**:贴吧是"盘链主源",B站是"账号发现主力",知乎是"盘链补源",
小红书**只是名字型计数**,不产盘链也不产热榜。

## 四、newsnow 多平台监控:现在的真实状态

### 4.1 它本来负责什么

`hot_sources.SOURCES` 共 **43 个源** = **2 个自研**(B站排行 / 豆瓣电影,直连公开 API)
+ **41 个走 newsnow 容器**(`http://127.0.0.1:4444/api/s?id=<平台>`)。

那 41 个含:**知乎热榜、微博热搜、快手、爱奇艺、头条、凤凰、澎湃、腾讯热榜、贴吧、
掘金、36氪、IT之家、少数派、酷安、GitHub Trending、财联社、华尔街见闻、雪球、金十、
虎扑、懂球帝**……(完整清单见 `hot_sources.py:146-206` 与 `:298-321` 的中文标签映射)

### 4.2 为什么现在**全黑** —— 两个原因叠在一起

| # | 事实 | 后果 |
|---|---|---|
| 1 | 本机 `SCHEDULER_ROLE=wechat`,而 `hot_source` 作业 `role=hotspot` ⇒ **本机根本不注册**(`scheduler.py:363-399`) | 本机不跑热榜,容器没人调 |
| 2 | 唯一会跑热榜的**远程**实例,`HOT_NEWSNOW_URL` **从未配置**(全仓库无此设置),默认 `127.0.0.1:4444` —— 在 redu-api 容器里这指向**容器自己** | 远程 41 个源**全空**;`settings.py:243-247` 的注释与实测都印证了这点 |

⇒ 本机 `hot_source_items` **冻结在 2026-10-01 16:53**(`ok=42 items=903`,那是扩容到 42 源后的验证轮),
此后 3 天没有任何新数据。**只有 B站 + 豆瓣两个自研源还在产数据。**

### 4.3 最糟的一点:**这是静默降级,没人收到告警**

`check_optional_containers`(探测容器存活)只在 `hot_sources.py:270-273` 被调 —— 也就是
**在被角色挡掉的那个作业里**。而它在远程探的又是容器内的 `127.0.0.1:4444`。
⇒ **两端都探不到真相,41 个源黑了 3 天,零告警。**

## 五、最优方案

### 原则

本项目自己的架构原则就写着 **「命门自持」**(`hot_sources.py:2-13` 的四层:契约层自持 /
实现层双路线 / 资产层入自己库 / 保险层镜像快照)。**newsnow 本来就是这条原则的"长尾妥协"**,
现在它成了单点 —— 应该按原设计往下走:能自研的自研,自研不动的再说。

### P0(先做,零代码或极低成本)

| # | 做什么 | 为什么 | 代价 |
|---|---|---|---|
| 1 | **让 newsnow 数据先回来**:远程 `.env` 配 `HOT_NEWSNOW_URL=http://172.17.0.1:4444`,并把 newsnow 容器部署到 VPS 宿主机(绑 `0.0.0.0`);或在远程实例上把 `SCHEDULER_ROLE` 确认为 `hotspot` | 41 个源黑了 3 天。**这是纯配置**,不配就一直是 0 | 一行配置 + 容器搬迁 |
| 2 | **给"可选源容器不可用"补一条真能到达的告警** | 现在这条探活挂在本机不跑的作业里 ⇒ 静默降级 | 小(把探活挪到本机也能跑的位置,或改为心跳检查) |
| 3 | **先核对远程到底是什么角色**(`job_heartbeats` 里有没有 `hot_source`) | `operations.md` 里远程角色本身就是 ⚠️ 待办,可能两端都没在跑 | 零(查一下) |

### P1(自研替代,摆脱容器 —— 用户明确要的方向)

| # | 做什么 | 为什么可行 | 代价 |
|---|---|---|---|
| 4 | **给自研 `WempClient` 补 `search_mp` + `add_feed`** | 这是**唯一**还需 WeRSS 的能力(§2.1),补上就**彻底不依赖容器**。自研客户端现在只有 `mp_articles`(`wemp_client.py:65`),而 `_subscribe_by_name` 要的是 `search_mp`→`fakeid`→`MP_WXS_*` | 中。凭据已有(`wemp_cred_1`),但那条路卡在 `200013` 频控 —— **低频调用(每天几次)大概率没事**,值得一试 |
| 5 | **知乎热榜自研** | 库里**已有可用的知乎 Cookie**;热榜直连 401 是"未登录",带 Cookie 应可解。B站/豆瓣的自研直连已是现成范式 | 中。Cookie 会过期要维护 |
| 6 | **微博/百度热搜自研** | 这两家**公开接口已知且免登录**(`外部接口速查.md`:微博 `/ajax/side/hotSearch`、百度 `/api/board`),而现在它们被算在 newsnow 的 41 个里 | **低**(两个纯函数) |

### P2(提高现有产出)

| # | 做什么 | 收益 | 代价 |
|---|---|---|---|
| 7 | **贴吧盘链"发现当轮立即转存"** | 现在一轮 17 条里 15 条是死链(被和谐)。缩短"被发现→被和谐"的窗口是**唯一有效解** | 转存更占盘/更易限流 |
| 8 | **知乎搜索词补限定后缀** | 裸词命中 **0%**,补"网盘/资料"后 **17.8%**。在 `.env` 配 `PAN_DISCOVERY_TERMS` 即可 | 零(纯配置) |
| 9 | **小红书名字型限流** | 单关键词 ~277s(逐条拉详情),4 平台×3 词可能 20~30 分钟 | 样本略减 |
| 10 | **MediaCrawler 补丁持久化** | 小红书修复只在 `patches/` 里,而 `tools/` 是 gitignore 的独立克隆 ⇒ **重装即丢**(2026-10-04 就是这么整轮挂的) | 一个 ~20 行自检脚本 |
| 11 | **MediaCrawler 登录态失效接告警** | 扫码过期现在**静默失败**,没人知道 | 小 |

### 明确**不做**的

- **不删 WeRSS**(`search_mp` 在用,§2.1);等 P1-4 落地后再评估。
- **不给小红书加盘链发现**(已实测否决:外链率 2.5%、盘链 0,样本 79 条)。
  但**结论要设复查**——本仓已两次栽在"写死的结论腐烂"上(贴吧就曾从"❌ 排除"翻案成"主源 56%")。
- **不把 B站 塞进 MediaCrawler 轮换**(实测它起不来:找 Chrome,本机只有 Edge;280s 卡扫码)。
  B站已有自研 API 路。

## 六、今天该记的两条教训

1. **「它这方面没用」≠「它没用」。** 我因为 WeRSS 抓不到文章就删了容器,
   而它真正在用的是**另一个能力**(号名→编号),差点把收录链的解析器删掉。
   **删任何东西之前,先把它被引用的每个能力过一遍。**
2. **静默降级比硬失败更贵。** newsnow 那 41 个源黑了 3 天零告警 ——
   因为探活被放在了**永远不会执行的那一侧**。这与本仓反复出现的
   「静默失败=假成功」是同一类:**告警挂在没人跑的地方,等于没有告警**。
