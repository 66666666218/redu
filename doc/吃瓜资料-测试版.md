# 吃瓜资料 · 测试版(2026-10-25)

> 目标:把**热点**做成一份可发的《吃瓜资料》(PDF / Word),用于拉新。
> **当前状态:本地测试版,未接生产** —— 不排程、不推送、不上传网盘。

## 怎么跑

```bash
# 标题 + 素材(素材可以是:一段文字 / 一个 .txt|.md 文件 / 一个网址)
python scripts/gossip_doc_test.py --title "某热点事件" \
    --source "某站报道:……" --source D:/tmp/report.txt

# 已经有一份 markdown,只重新排版(不再调模型)
python scripts/gossip_doc_test.py --from-md data/_gossip_test/xxx.md
```

产物:`data/_gossip_test/` 下同名的 **.pdf / .docx / .md**(md 留着是为了一次生成、多次排版)。

## 一条硬约束:模型**只整理,不创作**

`llm_client._GOSSIP_SYSTEM` 里写死了五条,其中前两条是这条链的底线:

1. **只能使用素材里已经出现的信息**;素材里没有的一律不写,**禁止用模型记忆补充**
   (人物、时间、金额、聊天记录、动机);
2. 未经证实的内容必须原样标注「网传」或「据<来源>报道,未经证实」;
3. 不写未成年人、住址/电话/身份证/账号;
4. 不下道德或法律结论(不写「渣男/实锤/违法」这类定性);
5. 中性克制的资讯口吻。

**为什么**:吃瓜内容里编一个细节就是造谣 —— 这是整条链唯一会**直接违法**的环节。
所以 `compose_gossip_doc()` **没有素材直接返回 None**,脚本也随之拒绝运行,
不会"让模型先写着看看"。

另外渲染前有一道闸:**内容里没有「免责声明」小节就不出文件**(`gossip_doc._check`)。

## 文档结构(固定七节)

`事件概览 / 时间线 / 涉及人物 / 当事方与相关方回应 / 争议焦点 / 信息来源 / 免责声明`

其中「信息来源」和「免责声明」是**必须**的两节,前者让读者能自己核,后者把定性责任交回读者。

## 实测样例(纯虚构,只验证管线)

```
✓ 标题:某演员与歌手被拍到同餐厅用餐,工作室回应私生活不便回应
  PDF : data/_gossip_test/示例_虚构_某演员与歌手聚餐事件_20261025_1912.pdf (37K)
  DOCX: data/_gossip_test/示例_虚构_某演员与歌手聚餐事件_20261025_1912.docx (36K)
```

模型的表现符合预期:把"网友称交往两年""聊天记录截图"都标成了**未提供证据 / 内容存疑**,
没有替任何一方下结论。

# 第二步:从热搜里**筛**出该做哪条(2026-10-25)

```bash
python scripts/gossip_topics_test.py            # 三平台热搜 → 吃瓜候选(带判定理由)
python scripts/gossip_topics_test.py --json     # 机器可读,供下一步喂给资料生成
python scripts/gossip_topics_test.py --no-llm   # 只用关键词(不花钱、应急)
```

## 三个来源都是**实时**取的

| 平台 | 入口 | 实测 |
|---|---|---|
| 微博 | `collector.fetch_hot_search`(要 Cookie) | 52 条 |
| 百度 | `baidu.fetch_hot`(免登录) | 30 条 |
| 抖音 | 公开接口 `iesdouyin.com/.../hotsearch/billboard/word/` | 50 条 |

⚠️ 抖音原先走的「热点宝」Cookie **已失效**(`DouhotAuthError`),而 `douyin.com/hot` 页面会给
**验证码中间页** ⇒ 改用公开榜单接口,免登录。

⚠️ 本机库里 `weibo_hot_items`/`baidu_hot_items` 停在 **09-29** —— 那是**远程 hotspot 侧**在跑。
所以这里**不读库、直接抓**,也**不写库、不排程**。

## 两道筛选:关键词打底 + 模型定夺

1. **关键词**(`gossip_topics.score`):强信号★3(恋情/出轨/离婚/官宣/塌房…)、弱信号★1、
   **硬排除**(时政/灾害/体育比分/财经)。便宜、可解释,但**分不清"公众人物"和"普通人"**。
2. **模型**(`judge_all`):把**全部**热搜交给模型判「是不是公众人物的私生活/关系/争议」。
   关键词只留作**排序**和"模型挂了"时的兜底。

### 为什么两道都要(当天实测的三种翻车)

| 现象 | 只用关键词 | 只用模型 |
|---|---|---|
| 「老板回应南开学生时薪高10元」 | ❌ 收了(命中"回应") | ✅ 剔掉 |
| 「张雪把县委书记丢河里」 | ✅ 硬排除挡住 | ❌ 模型判成"争议事件、可吃瓜" |
| 「章子怡肖战怎么认识的」 | ❌ 漏了(一个瓜词都没有) | ✅ 收进来 |

⇒ 结论:**黑名单要在模型之前生效**(`judge_all` 先过 `_BLOCK`),
**召回要交给模型**(判全部,不只判关键词筛过的)。

### 实测结果(2026-10-25 19:4x)

```
热搜共 130 条(微博/百度/抖音)
AI 判定:全部 109 条热搜 → 保留 12 条
 1. [抖音] 王楚淇终于结婚了        网红结婚属私生活
 2. [微博] 廖碧儿承认恋情          明星承认恋情
 5. [微博] 章子怡肖战怎么认识的    明星关系引猜测
 …
11. [百度] 女主播1800万买大平层…   网红争议
```
精度约 8/10:仍会有「春晚总导演任命」「女主播买房纠纷」这类被判错,
所以输出里**每条都带理由**,由人来拍板。

# 第三步:素材自动采集(2026-10-25)

```bash
# 一条命令:标题 -> 自动采素材 -> 出 PDF/Word/MD
python scripts/gossip_doc_test.py --title "廖碧儿承认恋情" --auto-material
```

## 各平台实测状态

| 平台 | 入口 | 状态 |
|---|---|---|
| **百度资讯** | `m.baidu.com/s?tn=news`(**移动版**;PC 版是客户端渲染,只有哈希类名) | ✅ 每个词 8 条报道标题/摘要 |
| 微博 | `weibo_search.search`(**必须传 session**,否则读不到加密库里的登录态,只会去 `.env` 找) | ✅ 每个词 13 条,正文较完整 |
| 抖音 | `douyin_cdp_source.search` | ⚠️ 时好时坏:18:xx 能出 16 条;19:2x 起返回**「验证码中间页」** |

⚠️ **百度这条的坑**:页面里混着**结构化字段残渣**(`"}]…isEncoding`)、**相关搜索词堆叠**
(`A |B |C`)和**评论区留言** —— 不剔掉的话,资料里会出现一堆"网友猜测"。
`_BAIDU_NOISE` 现在把这些都挡掉;命中词被 `<em>` 包住留下的中文间空格也一并收掉。

素材顺序是 **百度资讯 → 微博 → 抖音**:报道类放最前,模型写"事件概览"时先看到的是报道,
不是网友发言。

⚠️ **抖音这次踩到的坑值得记**:捕获到 `0` 条时,原实现会报"一条都没读到" ——
而真相是**页面被换成了验证码中间页**(HTTP 200、body 几乎空白)。
现在 `_GRAB_JS` 会单独识别 `验证码中间页` 并抛出**不同的措辞**,
`gossip_material` 再把它放进 `fails` 打出来。**"没内容"和"被验证"不能同形**。

## 实测(真实热点,不是虚构样例)

```
$ python scripts/gossip_doc_test.py --title "廖碧儿承认恋情" --auto-material
… 自动采素材:{'微博': 8, '抖音': 0} · ⚠️ 失败:{'抖音': '…「验证码中间页」…'}
… 整理素材(1264 字)→ 生成中
✓ 标题:廖碧儿承认与吕礼章恋情 并回应刘恺威新恋情传闻
  PDF / DOCX / MD 均已生成
```

生成结果里能看出"只用素材"这条约束真的生效了:

- 「刘恺威、黎纪君:**素材中未见当事方回应**,相关恋情为网传」——没有替他们编回应;
- 「信息来源」列的是**实际那几条微博账号**(@神奈川的小獭酱 / @小冬青- / @新浪娱乐 …);
- 时间线全是「时间未明确」——因为微博正文里本来就没有日期。**不知道就说不知道**。

## 还缺什么

- **抖音素材**:现在被验证码挡住,需要等风控窗口过、或换一个未被打过的号;
- **素材增量**:目前每个热点只搜一次一个词,没有"多搜几个相关词再合并"。
- **百度正文深度**:移动版给的是**标题+摘要**,不是整篇报道;要更实的素材得再进一步抓正文。

## 夸克没有上传接口,所以上传走浏览器

夸克的**读/写**接口都是纯 Cookie 认证(`QuarkTransfer._request` 就是带 Cookie + 公共参数的
普通 JSON 请求,不需要签名),但**上传不在其中**。

而网页版本身是登录着的(实测 `62.9TB/86TB`)⇒ 用**普通命令行启动的 Edge** + CDP 接管,
把本地文件塞进页面上的 `input[type=file]`,等价于人点「上传文件」。
**建分享不用浏览器**:`QuarkTransfer.share_fids()` 直接可用。

## 一次实测的完整链路

```
→ 目标文件:data/_gossip_test/廖碧儿承认恋情_20261025_2120.pdf
✓ 盘里已有同名文件,跳过上传
✓ 分享链:https://pan.quark.cn/s/33c22ce11b0e
✓ 已发管理群
```

**分享内容核验过**(不信"接口说成功"):`_list_share_files` 读回来就一个文件 ——
`廖碧儿承认恋情_20261025_2120.pdf`,`63083` 字节,无提取码。

## 两个踩过的坑

1. **搜索索引有延迟**:文件已经传上去了,`search_files` **120 秒都没命中**,
   而 `list_recent` 立刻看得到。只查搜索会得出「没传上去」的**假结论**
   ⇒ `_find_file` 两条路都查,搜索抛错也退回最近列表。
2. **同名文件不重复传**:重复上传会在盘里留一份 `文件(1).pdf`。上传前先 `_find_file`。

## 边界

- 发的是**管理群**(`FEISHU_WEBHOOK_ADMIN`),文案里写明「测试物料」——**不发客户群**。
- 夸克盘里会越堆越多测试文件;要清得单独做(现有 `pan_auto_clean` 是按监控源匹配的)。
- 百度盘这条路**现在走不通**(超额 43 倍,写不进去);迅雷未验证上传。
